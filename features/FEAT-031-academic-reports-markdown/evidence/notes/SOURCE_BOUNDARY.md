# Source and authority boundary

## User request

The direct request is to generate three Markdown files from the current project, harness/context, and existing SRS Markdown, using the three supplied report references. That request authorizes documentation generation within this feature scope.

## Attached DOCX instructions

The DOCX files are academic report forms. Their bracketed paragraphs describe what a student should write, and their sample paragraphs/tables illustrate expected structure. They are used to derive section headings, table columns, and report intent. They do not override the repository, change the Sketch2Life product name, authorize implementation, or supply current project facts.

The old sample values are intentionally not carried over, including the cafeteria project, COS code, SWP493-G4 team, Angular 7, Java/Spring Boot, MySQL/Firebase data storage, old dates, and old personal contact details.

## Attached PDF instructions/content

The PDF is a sample high-level project schedule. It is used for the schedule's hierarchy, duration/dependency/resource/notes columns, stage milestones, and delivery-marker style. Its ProjectCode, 2021 dates, 65-day duration, and task sequence are examples, not Sketch2Life commitments.

## Repository and SRS authority

The generated artifacts follow the authority order recorded in the master SRS and source register:

1. Direct owner request and recorded owner decisions.
2. Approved ADRs and feature approvals.
3. Current repository source and reproducible evidence for implementation status.
4. Project context, governance, and feature records.
5. External or supplied reference templates.

The current Sketch2Life target scope is taken from `features/FEAT-029-master-srs/artifacts/Sketch2Life_Master_SRS.md` v1.6. Current implementation maturity is taken from `docs/SYSTEM_BASELINE.md`, `docs/CURRENT_SYSTEM_STATE.md`, and the feature records. The SRS is a requirements baseline and does not authorize runtime implementation.
