# Feature decisions

## 2026-10-28 — Qwen-only Modal development service

- Use the existing candidate `QWEN3_VL_8B_INSTRUCT_BF16_V1`: `Qwen/Qwen3-VL-8B-Instruct`, immutable revision `0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`, BF16. “8B” is the model size.
- Implement a custom Modal ASGI Web Function and reuse the existing `tools.lightning_vision_v2_server.vision_v2` handler. Do not use the separate managed catalog Endpoints API for this custom contract.
- Expose only `/health` and authenticated `/v2/vision`; no SAM2.1 route, ASR, video route or model is included in the Modal endpoint.
- Store exact pre-staged weights in a read-only Modal Volume and inject `LIGHTNING_DEV_AUTH` with a Modal Secret. Disable automatic model downloads.
- Begin with one L40S (48 GB VRAM listed by Modal), a single-container maximum and scale-to-zero; actual memory, latency and cost require a separately authorized live measurement.
- Development configuration only. FEAT-003's model-quality gate remains not ready for production/runtime-default use. Project production selection stays Runpod under ADR-0005.
- Scope and evidence: `plan/PLAN.md`, `approvals/TASK_APPROVAL.md`, and `evidence/MODAL_QWEN_SETUP_20261028.md`.

## 2026-10-29 — Authentication before inference

- Auth-only requests use a generated synthetic PNG and omit media-admission provenance. They must be rejected without invoking Qwen; no admission PASS is invented.
- The owner reported rejection of a request missing Bearer and HTTP 401 for a deliberately incorrect Bearer. Correct-Secret behavior still requires evidence before a real synthetic inference request.
- The owner later reported replacing the Secret. Restart the temporary serving session before testing the replacement, because existing containers can retain the previous injected environment. No positive-auth result or local backup success is asserted without the corresponding owner output.
- The owner supplied shutdown output confirming that the previous temporary App was aborted. That output also confirmed the earlier HTTP 200 health and two HTTP 401 auth responses; its HTTP timings do not establish Qwen cold/warm inference performance.
- After the replacement, an owner-operated request using the local encrypted backup returned HTTP 422 at the admission gate. This verifies credential acceptance without model inference. Prepare an actual admission result for synthetic input before an inference request; do not fabricate a PASS.
- Use the existing image-only admission service and decoder in the existing backend environment for synthetic preparation; it does not need audio or GPU work. The owner confirmed those imports and reported `ADMITTED` for a new synthetic house-and-sun fixture. Preserve the actual admission artifact alongside the prepared request before inference.
- Diagnose the owner's local process-launch denial before retrying inference. Do not infer that the prepared input or Modal runtime failed from an error that occurred before the local probe started; no privilege escalation or security-policy change is proposed.
- The same interpreter launched successfully for the owner's version check. Isolate a harmless short code invocation next; argument length, native argument handling and application-control causes remain unconfirmed.
- The owner's short code and harmless stdin checks also succeeded. Prepare a readable source file and perform local syntax inspection before another inference attempt, without changing security settings or treating any hypothesized launch cause as proven.
- The owner prepared the file-based probe and reported its successful AST syntax check. Keep credentials on stdin and retain only response metadata, counts and client wall timings; do not store raw model output or retry a failed first request automatically.
- The first admitted remote request returned typed `MODEL_LOAD_FAILED` despite HTTP 200. Treat it as a failed model-load attempt, not successful inference or a cold-latency measurement. Inspect existing serve logs before proposing a runtime change or another GPU request; the adapter and persistent worker deliberately discard underlying load exceptions, so the logs may not contain a traceback. No root cause is established.

Preserve the existing admission receipt and source identities; CPU processor success does not establish GPU inference or quality readiness.

Keep pinned identity/config and attempt-number checks, and preserve safe observed metadata when correcting the probe rather than discarding it or changing runtime behavior.
