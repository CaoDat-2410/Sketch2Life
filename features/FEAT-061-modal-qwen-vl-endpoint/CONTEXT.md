# FEAT-061 Modal Qwen3-VL development endpoint

- Status: REVIEW
- Owner: Project owner
- Numbering: drafted as FEAT-048 and renumbered FEAT-061 on 2026-10-29, because FEAT-048 is already used on `origin/dev` by `FEAT-048-be2-vision-correction` and `FEAT-048-be2-content-publication`. `plan/PLAN.md` and `approvals/TASK_APPROVAL.md` are intentionally unchanged so the approved plan SHA-256 still matches; they, and the receipts in `evidence/modal-smoke-20261029-v1/` (`admission.json`, `request.json`, inference metrics), still say FEAT-048 or carry `artifact_ref` paths under the old folder name. Read all of them as this feature.
- Goal: provide a separately configured Modal development endpoint for only the existing Qwen3-VL Vision V2 route, with SAM2.1 excluded.
- Scope: local deployment configuration and safe account setup instructions. No Modal cloud resource, GPU call, secret, model upload, or endpoint deployment is part of this task.
- Non-goals: SAM2.1, ASR, video/Wan2.2, model prompt/profile tuning, quality re-study, backend/mobile integration, and production provider replacement.
- Dependencies: Modal Python SDK/account and GPU billing for a future remote run; staged exact Qwen checkpoint in a named Modal Volume; runtime Secret containing the endpoint bearer token.
- Risks: runtime CUDA/PyTorch compatibility, 48 GB L40S cost while running, cold-start/model-load delay, and the previously recorded Qwen quality `NOT_READY` result.

## Context snapshot

- Owner directly asked to remove SAM2.1 from the planned Modal endpoint and configure Qwen3-VL first on 2026-10-28.
- [Project context](../../../docs/context/PROJECT_CONTEXT.md) records Lightning as the current dev inference provider and Runpod as production. This Modal endpoint is a scoped development experiment only.
- [FEAT-003 Phase B evidence](../../FEAT-003-multimodal-understanding/evidence/notes/P2_T3_PHASE_B_B5_RECOMMENDATION.md) identifies the single candidate profile as `QWEN3_VL_8B_INSTRUCT_BF16_V1`, model `Qwen/Qwen3-VL-8B-Instruct`, immutable revision `0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`; its quality recommendation is not production/runtime-default approval.
- The approved versioned request/response logic lives in `tools/lightning_vision_v2_server.py` and `backend/src/sketch2life/contracts/schemas/vision_v2.py`. The wrapper will expose its existing authenticated `/v2/vision` handler and `/health` only.
- The main Modal Endpoints product manages catalog/custom model serving through a separate standard API. The required Sketch2Life request shape is instead served by a custom Modal ASGI app.
- Use a read-only Modal model Volume and explicit runtime secret. The existing Qwen runtime defaults to no model downloads and computes in BF16 on CUDA.
