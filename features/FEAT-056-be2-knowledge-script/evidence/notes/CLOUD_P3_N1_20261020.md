## Correction

The domain comparison now removes the Unicode 15.0 `Default_Ignorable_Code_Point` property
in addition to the existing Cf removal. The explicit merged ranges come from the official
[Unicode 15.0 DerivedCoreProperties data](https://www.unicode.org/Public/15.0.0/ucd/DerivedCoreProperties.txt).
Filtering happens before NFKC so CGJ inserted between a Vietnamese base and accent cannot
prevent their canonical composition. Filtering and NFKC also follow casefold. The property
table is fixed policy data; no dependency or runtime data download is introduced.

Domain text validation and strict DTO text validation share a Cc-control predicate. LF and
TAB remain allowed; DEL and the C1 range are rejected. Submitted text is never silently
cleaned. Ordinary combining accents remain meaningful. Stored text, projected text and
canonical NFC serialization retain their established behavior and original default-ignorable
code points. The producer examples artifact was not modified.

## Limits

Default-ignorable folding can conservatively equate emoji or complex-script variants. It
does not remove ordinary Vietnamese accents, merge arbitrary word boundaries, perform semantic
truth verification, or promise recognition of every homoglyph or paraphrase. Full cloud raw
report archival and conditional `cloud-review` cleanup are tracked separately by the parent.

Component remains NOT_ACCEPTED; card remains IN_PROGRESS / NOT_DONE.
