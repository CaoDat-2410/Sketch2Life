## Failure and correction

The historical portable verifier relied on assertions, including export hashes and the
requested Git commit. Python `-O` and `-OO` disable those checks. Reproduction on isolated
copies of the original `f0359c4fbb7c3f4a35dd3f2265559779a17951e9` product/export snapshot
confirmed six false-success outcomes: both optimization modes printed
`PORTABLE_EVIDENCE_VALID` for valid input, a wrong expected commit, and tampered README bytes.
The normal-mode baseline passed, and its wrong-commit and tampered-byte controls failed as
expected. The red regression driver therefore exited 1 with 3 expectations met and 6 failed.

The two-line guard in `evidence/cloud-review/verify_evidence.py` now uses an explicit
`parser.error` when `__debug__` is false, before reading provenance or printing any success.
Internal assertion-based checks retain their normal-mode behavior; this change does not
claim they remain active under optimization. Running the verifier requires normal Python.

Raw commands, stdout/stderr, per-case exit codes and SHA256-bound logs are in ignored local
`evidence/local/cloud-p3-verifier-20261020/`; `probe_verifier.py` is the regression driver.
The `red/` and `green/` folders retain separate no-overwrite summaries and all nine cases.

| Mode | Valid historical fixture | Wrong expected commit | Tampered payload |
|---|---|---|---|
| Normal | exit 0, expected success token | exit 1, HEAD assertion | exit 1, export size assertion |
| `-O` | exit 2, no success token | exit 2, no success token | exit 2, no success token |
| `-OO` | exit 2, no success token | exit 2, no success token | exit 2, no success token |

The green driver exited 0 with all 9 expectations met. Every optimized case reports the
explicit instruction to rerun without `-O` or `-OO`. These are actual subprocess executions;
an import/collection failure is not counted as a killed regression.

The fixtures contain the original pinned product and selected files, frozen authorization,
profile, acceptance map and portable export. They use the ancestor task checkout's unchanged
starting HEAD for the explicit Git comparison. No Git metadata was copied or modified.
Only the corrected verifier and its derivative inventory were overlaid on the green fixture.
New product changes from P3-N1 intentionally do not qualify as the old historical snapshot.
