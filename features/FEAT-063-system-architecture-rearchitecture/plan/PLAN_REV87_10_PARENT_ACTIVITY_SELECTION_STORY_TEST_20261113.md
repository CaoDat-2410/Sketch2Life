## 1. Purpose

Rev87.9 completed two real Qwen3.5 inferences, then the story request returned HTTP 422. This was not caused by the activity quality gate: the activity response was HTTP 200 and passed the current gate. The Parent UI has no primary-activity selector. The story request schema requires the suggestion request ID and activity reference, and the story worker input currently omits the selected activity.

This bounded follow-up adds a **test-only, non-persistent selection bridge** so the real UI can select one activity returned by the current run's real AI request and pass its exact server-validated snapshot to Qwen story generation. It also temporarily bypasses only the soft activity quality checks in the task-local API container. Hard safety, schema, age, privacy, authorization and outdoor-setting checks remain enabled. This test bridge is not production-ready and does not establish durable activity-selection persistence.

## 2. Exact objective and flow

Run a new synthetic Parent account through the actual Pixel_10 Android app and the current-worktree backend:

1. Sign up through the app and create a synthetic profile with local synthetic authorization.
2. Use the existing generated chicken drawing; do not create or substitute another image.
3. Upload it through Android gallery, confirm context, run Qwen3.5-VL drawing analysis and confirm the subject in the UI.
4. Request activity suggestions once from the real catalog-first API and Qwen3.5 worker. The optional SVG guide stays skipped because the shared dev DB is missing its SVG catalog tables; do not retry its lookup or run a migration.
5. Render the actual returned cards with selection affordances. The adult selects one result from this request in the UI; no ID or activity body is manually injected.
6. The backend validates the selected request ID/ref against a short-lived in-memory snapshot created by the same authenticated suggestion response, bound to the same owner, StoryRun and understanding revision. It passes the exact selected activity snapshot to the story worker.
   Because `primary_activity` and its integrity hash become required worker inputs, the story-generation input contract advances to v2 atomically in the backend client and Modal worker; there is no silent v1 fallback.
7. Generate one real Qwen3.5 story draft, show it in the actual UI, and confirm it through the adult review action if the result passes the existing story schema/safety validation.
8. Do not create a video. No audio, transcription, FLUX, SAM2, topic retake, alternate activity request, story rewrite, or output retry.
