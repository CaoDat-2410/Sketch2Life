# Rev87.16 — Make Qwen catalog stroke assignment coverage reliable

**Date:** 2026-11-15<br>
**Status:** APPROVED by the owner's direct instruction: “fix luồng đi”.<br>
**Baseline:** FEAT-063 v2.7-draft. Preserve product requirements in §§1–31; record implementation evidence in §32 only.

## Observed failure

Rev87.15 uploaded and verified the Openclipart corpus on Modal Volume v2, deployed the Qwen3.5 app, and passed CPU `/health`. One real synthetic `con mèo` worker request reached output validation but failed with `SVG_CATALOG_STROKE_PLAN_PATH_COVERAGE_INVALID`. The raw Qwen output was not logged, so the previous run cannot establish whether IDs were missing or repeated. It was not a timeout. No retry was sent.

The current contract asks Qwen to emit arrays of `path_ids` grouped inside 4–8 stages, then requires the concatenated arrays to cover every selected source path exactly once. The JSON schema constrains each value to a known path ID, but cannot require set equality across those arrays. This leaves a predictable coverage failure to a free-form model decision.

## Goal

Keep Qwen responsible for pedagogical ordering and Vietnamese teaching copy while making exact source-path coverage structurally explicit and diagnosable. The final SVG must still use only the pinned catalog source geometry; no gate is relaxed and no geometry is generated by Qwen.

## Approved implementation

1. Replace grouped path arrays in the catalog-plan output with a versioned plan containing:
   - 4–8 ordered stages with short Vietnamese labels/instructions;
   - one `path_stage_assignments` JSON object whose property set is exactly the selected source path IDs and whose integer values select a stage.
2. Build a dynamic constrained schema from the selected SVG path IDs: all source IDs are required properties, unknown properties are forbidden, and stage values are bounded. Reject duplicate JSON object keys explicitly before normal parsing can collapse them.
3. Validate stage indexes against the returned stage count, require every stage to receive at least one source path, and derive each stage's `path_ids` deterministically from source order. Preserve exact path data, source hash, dataset revision, sanitizer and existing safety/complexity checks.
4. Add safe failure diagnostics containing only counts and reason codes (expected, assigned, unique, missing, duplicate-key, out-of-range and empty-stage counts as applicable). Never log prompts, raw model output, SVG contents, child data or credentials.
5. Add focused local contract tests for valid complete assignments and malformed/missing/unknown/duplicate keys, invalid stage indexes, empty stages, and source-path preservation through rendering.
6. Deploy the updated existing language/audio Modal app in `dev`, verify CPU `/health`, then send **at most one** new real synthetic `con mèo` beginner request through the deployed catalog worker. Validate the returned contract and exact path coverage if a guide is returned. On any terminal failure, preserve evidence and stop without retry.
7. Record logs, timings, failure reason or returned guide hashes and acceptance state in a new EV-063-111 evidence folder. Update FEAT-063 context, source register, status, evidence index and SRS §32 only.
