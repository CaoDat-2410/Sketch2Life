## Baseline

- The combined FastAPI app already serves Swagger UI at `/docs` and OpenAPI JSON at `/openapi.json`.
- Rev37 declares 135 operations: 124 mounted operations across 111 OpenAPI paths and 11 candidate/fixture operations that are not mounted.
- Local Compose conditionally mounts three storage-example operations; the OpenAPI snapshot is expected to be generated with that local-only option enabled.
- Runtime OpenAPI is 3.1.0 and currently contains all 124 mounted operations. Operation purposes are missing from 123 operation descriptions. The single `{asset_ref:path}` to `{asset_ref}` path spelling difference is the standard OpenAPI path-template form, not a missing route.

## Goal

Make the existing interactive Swagger UI and generated OpenAPI JSON readable and traceable to every applicable Rev37 contract row, without changing which APIs run or how they behave.

## Scope

1. Enrich the runtime OpenAPI generated by `create_app` with Rev37 purpose descriptions, surface tags, exact request-input and authentication contract metadata, and source-handler/verification metadata for all 124 mounted operations.
2. Preserve FastAPI-generated request/response schemas, parameters, media types and security requirements; align response descriptions and ensure every Rev37-declared response code appears. Do not infer undeclared errors or security schemes.
3. For any declared response whose runtime payload differs from Rev37, expose both the contract schema and the observed runtime payload in OpenAPI, mark the discrepancy with a vendor extension, and record the evidence. Do not change endpoint behavior within this Swagger task.
4. Keep the 11 candidate/fixture operations out of active OpenAPI `paths`; expose their exact method/path/purpose and `not mounted` status in a root-level `x-unmounted-operations` extension and the feature evidence.
5. Identify the Rev37 source revision and its 135/124/11 operation counts in the OpenAPI info metadata.
6. Add a reproducible OpenAPI snapshot for the local Compose profile and an automated contract-completeness check, normalizing FastAPI path converters and checking request parameters, request-body presence/media/schema/requiredness, authentication/security parity, and response-code parity.
7. Update FEAT-063 context, decision, source, status and evidence records.

## Acceptance criteria

- AC1: Swagger UI remains available at `/docs`; `/openapi.json` is valid OpenAPI 3.1 JSON.
- AC2: The local Compose profile exposes exactly the 124 mounted Rev37 method/path operations across 111 paths; no mounted operation is missing or extra after standard path normalization.
- AC3: Every mounted operation has its contract purpose, a surface tag, all contract-declared request parameters and request-body schemas, matching authentication/security declarations, and traceable handler/verification metadata.
- AC4: The three local storage-example routes appear only when the existing local-only setting enables them.
- AC5: All 11 candidate/fixture operations are recorded as not mounted and are not represented as callable API paths.
- AC6: Existing request schemas, response payload schemas, auth declarations and route exposure remain unchanged; no product API behavior is added. Every Rev37 response code and description is represented; runtime/contract payload mismatches are clearly identified and both payload shapes are documented.
- AC7: The exported snapshot and automated checks agree with Rev37 operation, request-input, authentication and response-code declarations and identify any mismatch.

## Verification

## Explicitly excluded
