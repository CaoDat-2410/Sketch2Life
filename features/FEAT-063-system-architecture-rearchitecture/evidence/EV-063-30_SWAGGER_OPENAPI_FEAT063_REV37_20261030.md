## Runtime discrepancy reported

Rev37 declares HTTP 413 responses as `MobileWorkflowResultV1` for `POST /v1/sessions/{session_id}/media/audio` and `POST /v1/sessions/{session_id}/media/image`. The request-body limit middleware currently sends a generic body:

```json
{"code":"REQUEST_TOO_LARGE","message":"<safe message>","request_id":"request-body-limit"}
```

The Swagger 413 response documents both shapes with `oneOf` and carries `x-contract-runtime-mismatch`. No route or middleware behavior was changed in this documentation task.

The existing regression `backend/tests/contract/test_live_image_demo_api.py::test_image_upload_transport_enforces_a_hard_multipart_body_cap` fails at line 1394: it indexes `response.json()["failure"]["code"]` and gets `KeyError: 'failure'`. Its expected body is `failure.code == "UPLOAD_TOO_LARGE"`, while the middleware emits the generic body above. This mismatch remains an API/test issue for a separately scoped behavior fix.
