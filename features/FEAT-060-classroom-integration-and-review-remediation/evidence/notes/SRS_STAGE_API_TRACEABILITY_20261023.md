**Status:** Rev4 implementation traceability as of 2026-10-24; it is not evidence that every stage is end-to-end implemented. The original Rev3 table below is retained as a historical pre-implementation snapshot; use the current Rev4 table first.  
**Baseline:** `dev@0a7ce768c153f2104cff930569c3eda6e484532c` plus the preserved dirty working tree.  
**Canonical sequence:** FEAT-029 Master SRS, §B5 (rows around 184–198); detailed shared-stage semantics in §B19.4–B19.5.  
**Rule:** a UI screen, local fixture, or HTTP 2xx is not by itself a completed SRS stage. Mark a stage complete only when its required durable effect and transition guard are present.

**Implementation evidence:** see [`API_INTEGRATION_CATALOGUE_20261024.md`](API_INTEGRATION_CATALOGUE_20261024.md) for per-endpoint caller, purpose, side effect, UI/service connection, proof, and remaining gap. Current checks prove local build/typecheck/lint and deterministic/UI/backend contract behavior; they do not prove a live database-backed FE-to-BE session.

## 2. Historical Rev3 API catalogue: baseline caller, effect, and failure meaning

All BE1 paths below are prefixed by `/api/be1/v1`. Adult routes require a Firebase-verified `Authorization: Bearer <ID token>` plus organization/class role assignment. Device routes use `X-Be1-Grant` and `X-Be1-Device-Key`. PostgreSQL-backed operations fail closed if DB configuration is absent. Responses use `contract` names and request IDs; clients must surface error code/message and must never synthesize successful data.

### 2.1 Identity, registry, profiles, and consent

| Endpoint | Caller and payload/result | Why the screen calls it / durable effect | Limits that affect flow |
|---|---|---|---|
| `GET /organizations/{org}` | Adult; organization metadata. | Admin/Teacher verifies its selected organization scope. | Not a substitute for the current user’s role. |
| `GET /organizations/{org}/me` | Adult; verified identity/role view. | Login/bootstrap decides which authorized UI can be shown. | A Firebase login alone does not imply class assignment. |
| `POST /organizations/{org}/assignments` | School admin; subject, role, optional class. | Assigns authorized adult access. | Admin-only; not currently connected to UI. |
| `DELETE /organizations/{org}/assignments/{assignment}` | School admin. | Revokes adult assignment and audits it. | Not a child session revoke. |
| `GET /organizations/{org}/classes` | Adult; returns active classes visible through assignment. | Teacher setup loads selectable classes. | No fixture class should be appended client-side. |
| `POST /organizations/{org}/classes` | School admin; `{display_name}`; returns new `class_id`. | Admin creates a real class. | Not yet established as a current Admin UI integration. |
| `GET /organizations/{org}/classes/{class}/profiles` | Assigned adult; returns active `child_id`, `display_name`, `age_months`. | Teacher maps a privacy-preserving pending device request to a specific managed profile. | Fails closed if any listed profile’s consent is pending; pending request has no identity. |
| `POST /organizations/{org}/classes/{class}/profiles` | Teacher/admin; child/class/consent/purpose/display name/age months. | Creates managed profile and enrollment. | Requires effective consent; age range is 36–155 months. |
| `POST /organizations/{org}/classes/{class}/consents` | Teacher/admin; class/child/purpose/evidence ref. | Records consent evidence state as `pending`. | This call itself does not make consent effective. |
| `GET /organizations/{org}/classes/{class}/consents` | Assigned adult; list with state/effective flag. | Preflight consent review. | Effective remains determined by the backend policy, not UI text. |
| `POST /organizations/{org}/classes/{class}/consents/{consent}/revoke` | Teacher/admin. | Revokes consent; later protected actions must fail closed. | Must not be replaced by deleting UI state. |

### 2.2 Session, join/admission, groups, and turn control

| Endpoint | Payload/result | Role in the flow and connection |
|---|---|---|
| `POST /organizations/{org}/sessions` | `{class_id,purpose_ref,configuration}` → `Be1SessionV1` fields + one-time `join_code`. | Teacher setup creates a durable configured session. Configuration is currently generic JSON (max 8 KiB); supported UI fields need exact validation before SRS completeness can be claimed. |

| `POST .../sessions/{session}/lobby` | `{expected_revision}` → updated session. | Opens pending admission. `409 STALE_SESSION_REVISION` requires reread, not blind retry. |

| `POST .../join-requests/{grant}/admit` | Teacher `{child_id}` → membership ID/state. | Explicitly binds that request to a managed class profile. Checks active profile, duplicate membership, and effective purpose consent. |
| `POST .../join-requests/{grant}/revoke` | Teacher → grant `revoked`. | Rejects/withdraws device and closes current membership/turn as applicable. |
| `POST .../device-grants/{grant}/refresh` | Child device headers → `pending`, `revoked`, or `admitted` + rotated device key. | Polls for Teacher decision. Store rotated key in secure storage before next request. |

| `POST .../groups/{group}/control` | `{action:lock|unlock,expected_revision}`. | Locks/unlocks group writing and closes active turns when locked. |

| `POST .../memberships/{membership}/leave` | Teacher route. | Marks membership left and closes its active turns. Not equal to revoking whole session invite. |

## 3. Historical Rev3 gap snapshot — stage commands then missing

The current `/sessions/{session}/start|pause|resume|finish` endpoints control **lifecycle**. `/memberships/{membership}/progress` controls **one membership**. Neither API stores the shared 9-stage classroom position. There is no authoritative `GET current stage`, guarded `AdvanceStage`, explicit stage history, completion snapshot, or `Completed`/`EndedEarly` contract. API proposal is in `artifacts/BE1_SHARED_STAGE_CONTRACT_PROPOSAL.md`; it is not implemented.

The target stages are exactly `preparation → join → explore_draw → assistance → sharing → knowledge → off_screen → reflection → completion`. SRS v3.3/B28 requires next-stage-only transitions with a durable backend receipt; Assistance may interleave or be explicitly marked `not_needed`; arbitrary skips are forbidden; unfinished groups require `save_draft`. Return commands remain disabled until OD07 is resolved; OD07's final policy remains open. Group progress is independent from the shared class stage, so do not conflate stage with lifecycle or enforce UI-only stage changes.

## 4. FEAT-057 candidate APIs and Modal boundary

Candidate BE2 router files (`ai_jobs`, `assistance_requests`, `analysis_corrections`, `knowledge_video`, `video_review`, `video_failure`, `activity_execution`) are not mounted by `mount_classroom_routers()` in `backend/src/sketch2life/interfaces/http/router_composition.py`; classroom entrypoint mounts health + BE1 runtime only. Their tests/contracts do not mean a product endpoint or a connected FE flow exists. FEAT-057 remains the approval/adoption gate.

Modal belongs behind the backend AI-provider adapter after the AI contract is approved. Child/Teacher/Admin should never receive a Modal credential or call a Modal endpoint directly. Existing AI settings do not include a Modal provider and repository evidence proves no live endpoint. Hosting the complete API container on Modal is optional, not required to use Modal for bounded AI inference; see `artifacts/MODAL_HOSTING_BOUNDARY_REVIEW_20261023.md`.
