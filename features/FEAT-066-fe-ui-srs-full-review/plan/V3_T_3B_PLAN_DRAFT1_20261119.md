## 2. Decisions (SRS-cited)

- **T3B-D1 Route and request (l.1653).** `POST /v1/lesson-occurrences/{occurrence_id}/documents`, body `{ "asset_ref": "..." }` (`extra=forbid`; one field; organization, owner, file name, hash and type are server-derived, l.1637, l.1692). `Idempotency-Key` required. Scope and write rule are T3A-D3 (responsible `teacher` of the occurrence's class; unknown or out of scope 404; guide/observer 403; occurrence not writable 409 `INVALID_STATE_TRANSITION`).
- **T3B-D2 Which asset is attachable (l.1653 "upload session đã hoàn tất", l.1657, l.504).** The server finds the session by `core_upload_sessions.final_asset_ref = asset_ref` and requires: purpose `OCCURRENCE_DOCUMENT`, `target_ref` equal to this occurrence, owner equal to the caller, state `COMPLETED`, recorded scan verdict `CLEAN`. Anything else, including another actor's asset or another occurrence's, is the uniform 404 (no hint that the asset exists). The asset must not be attached already (`uq_srcdoc_asset`): a different key for the same asset is 409 `RESOURCE_CONFLICT`; the same key replays (T3B-D7).
- **T3B-D3 Verification before parsing (l.1653 "source hash do server xác minh").** The server reads the object through the storage port into a `SpooledTemporaryFile`, recomputing size and SHA-256 and comparing with `core_asset_metadata.content_sha256` and the session size: over 25,000,000 bytes 413 `LESSON_FILE_TOO_LARGE`; mismatch 422 `UPLOAD_CHECKSUM_MISMATCH`; object missing 422 `UPLOAD_INCOMPLETE`; storage fault 503 `STORAGE_UNAVAILABLE`. **No second AV scan** (T-2a scanned the same bytes through the T-2z adapter and recorded the verdict; a second scan doubles ClamAV cost for no new information); T-3b refuses an asset whose recorded verdict is not `CLEAN` (404 per D2, so a test-clean or unscanned asset is never parsed). The recorded scanner identity stays in lineage; T-3b never writes a verdict.
- **T3B-D4 Parser reuse (l.545, FR-T-06, UC-04).** The same `DeterministicLessonDocumentParser` instance (`app.state.lesson_document_parser`). Additive port change: `LessonDocumentExtraction.extracted_text: str = ""` filled by the parser from the `text` it already builds (bounded 2 MiB); the library service ignores it, so its behaviour is unchanged. The text becomes revision 1 (`origin=EXTRACTION`, `review_state=NEEDS_REVIEW`, hash of the UTF-8 bytes, `parser_name/version`, `page_coverage`, `extraction_warnings`). Pages without text in a document that has some are not refused: warning `OCR_NOT_SUPPORTED_PAGES` plus `page_coverage` (UC-04: scan pages are marked, no OCR, no provider call). A document with no text at all is refused (D5).
- **T3B-D5 Synchronous refusals, no failed job (§9.8, UC-04 l.1437).** Everything the parser or the checks reject is answered on the request, before any row is written, so no `source_documents` row or job exists for a bad file and the Teacher may replace the file. Mapping (new routes follow §9.8, not the library's 415 for OCR): `UNSUPPORTED_MEDIA_TYPE`, or detected type not equal to the asset's media type: 415 `UNSUPPORTED_LESSON_TYPE`; `OCR_NOT_SUPPORTED`: 422 `OCR_NOT_SUPPORTED`; `INVALID_SOURCE_DOCUMENT` and `DOCUMENT_EXPANSION_LIMIT_EXCEEDED`: 400 `INVALID_FILE_CONTENT`; `ENCRYPTED_DOCUMENT_UNSUPPORTED`: 422 `ENCRYPTED_DOCUMENT_UNSUPPORTED`; `DOCUMENT_PAGE_LIMIT_EXCEEDED`: 422 `DOCUMENT_PAGE_LIMIT_EXCEEDED`; `DOCUMENT_TEXT_LIMIT_EXCEEDED`: 422 same code. **The three specific codes are outside §9.8** (the SRS asks for "mã lỗi an toàn cụ thể", l.1437, and names none for encryption or page limits), kept as the library's own parser codes, added to `STATUS_MESSAGE_ONLY` with Vietnamese messages for the first two; recorded as a technical decision, owner may rename. Alternative (rejected): accept first and surface a failed job on `/v1/jobs`; it would leave rows for unusable files and break "replace the file".
- **T3B-D6 The job (TD-15, l.779, l.1653, l.806).** After the checks pass, one transaction on the request's `Session` connection writes: `lesson.source_documents` row, `lesson.document_revisions` revision 1, **one `ai_jobs.job` row already terminal** (`succeeded`, disposition `accepted`, one attempt started and finished at the same instant, history `created, started, succeeded:accepted`), an audit entry (`lesson.source_document.create`), and the receipt. The job is built by `domain.ai_jobs` functions (`create_job`, `start_attempt`, `succeed`) and inserted with `SqlAiJobUnitOfWork(db.connection(), no_fences).insert_job` by a new `InlineExtractionJobRecorder`; it writes **no outbox row, no queue message, no semantic or command receipt** in `ai_jobs`, so no worker can pick it up (test). Values: `job_type lesson_source_document_extraction` (registered in T0.4's registry for target kind `LESSON_SOURCE_DOCUMENT`), `JobScope(organization_id, session_id None, subject_refs (), purpose_code LESSON_SOURCE_EXTRACTION, target_id source_document_id)`, `RequestRef(request_id source_document_id, request_revision 1, input_hash asset sha256, context_revision 0)`, `ResultRef(artifact_ref "lesson-document-revision:<id>", sha256 extracted_text_hash, provenance "parser:<name>@<version>")`, named policy `lesson.inline.v1` (one attempt). The row id is stored in `source_documents.extraction_job_ref`. T-3b adds the registry entry's scope rule (a Teacher with a current teacher-family row on the class of the document's occurrence) and eligibility (result refs visible: no child data) in `application/job_kinds.py` per the T0.4 contract; production authorisation stays deny for other kinds. Atomicity across both schemas holds because they share one database connection.
- **T3B-D7 Keys and replay (l.1697).** Receipt in `be1_command_receipts`, scope `POST /v1/lesson-occurrences/{id}/documents`, fingerprint over `{occurrence_id, asset_ref}`; replay re-authorises, then returns the stored 202 body unchanged; another payload with the key is 400 `INVALID_IDEMPOTENCY_KEY`. Concurrency: lock the occurrence row `FOR UPDATE` and the session row `FOR UPDATE` before the unique insert; the loser of a race gets 409 `RESOURCE_CONFLICT`.
- **T3B-D8 Reads here (TD-05).** The attached document and revision 1 must be readable for review (l.1708), so the document and revision reads ship in T-3b; the edit is T-3c.
