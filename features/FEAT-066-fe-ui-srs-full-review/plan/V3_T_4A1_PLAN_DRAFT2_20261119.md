## 1. HEAD facts (verified)

- `story.runs`: `actor_scope_kind`/`actor_scope_ref` NOT NULL; **CHECK `ck_story_run_owner_kind` allows only `PARENT_ACCOUNT` and `ORGANIZATION`** (`20261102_story_run_lite.py:366`; frc08 does not change it); `profile_ref` String 128; lock `active_owner_parent_account_id` (unique partial index). No Teacher kind or lock column (DDL-B2, T-4b2). Receipts and review tables use the same two kinds with a free-text ref; only Core tables require `ORGANIZATION` ref = organization id.
- Guard at HEAD: `_require_parent` (`routers/parent_story_runs.py:86`) answers 404 for a non-Parent (T0.9). Handlers to retrofit: GET (351), context, subject and script confirmation (437, 465, 501). The legacy `/api/parent/v1/ai/...` family has its own guard and stays Parent-only.
- Ownership is decided in several places (not only `_owned_run`): the repository (site table below), `ParentRunArtworkResolver.resolve` (`infrastructure/uploads/resolvers.py:59-81`: run must be `PARENT_ACCOUNT` + principal digest, key prefix `parent/<run>/`), `attach_artwork`/`attach_uploaded_drawing` (asset owner scope `PARENT_ACCOUNT` + digest), and the `/v1/jobs/{job_id}` resolver (T0.4).
- Managed Profile child ids are `synthetic-<hex>` or UUID text (`be1_registry.py:1263`); `get_run` does `UUID(str(run["profile_ref"]))`. `confirm_story_revision` requires the SUBJECT decision by the same `actor_scope_ref`.
- Assignments: `be1_organization_assignments`; the class assignee is an active class-scoped `teacher` row (T-7a2). `be1_classrooms.state` is `active|suspended|archived` (T-7b). T-7d (9476f632) projects the child's class in `be1_managed_profiles.class_id`.
