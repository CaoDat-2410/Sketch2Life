## 1. HEAD facts

- `POST /v1/story-runs/{id}/subject-confirmation` (`parent_story_runs.py:462`) answers 200 `{request_id, story_run_id, understanding_revision, decision "CONFIRMED"}` or the lifecycle envelope for a replay of a purged run. A subject edit is already recorded synchronously as understanding revision N+1 (`CORRECTED_BY_ADULT`, repository `confirm_subject`), and the run moves to `PREPARATION_REVIEW`. No job exists.
- `POST /api/parent/v1/ai/story-runs/{id}/story-revisions` (`parent_ai.py:453`) is the only story route: `modal_dev` gate, key 1-200, one synchronous Modal call for the first story and every rewrite, `expected_understanding_revision`, optional `rewrite_instruction`. The repository refuses a hint-less rewrite (`PARENT_STORY_REWRITE_NOT_ALLOWED`) and a rewrite without a first story, and counts four revisions as the limit (`STORY_REWRITE_LIMIT_REACHED`). `/drawing-understandings` (T-2b) and `/sketch-guides` are the other two routes of the family.
- Guard of the family: `_require_parent` (`parent_ai.py:76`) answers 403 `PARENT_ROLE_REQUIRED` (not `ACTION_NOT_ALLOWED` as P-12 says; no client or test reads this code). Envelope: `app.py` already routes `/api/parent/v1/ai/.../story-revisions` and `/drawing-understandings` through the M2 story envelope (`_legacy_parent_story_revision_path`, `_parent_drawing_understandings_path`); only `/sketch-guides` keeps the raw FastAPI `detail` body (pinned by `test_http_error_conventions.py:133`). So P-35 ("raw detail codes") is true only for `/sketch-guides`.
- Android (`.worktrees/mobile`, HEAD `80fdc1a5`): `ParentApi.ts` still calls the legacy `drawing-understandings` (l.374) and `story-revisions` (l.226-243, `createStoryRevisionV1`); it has no code for `story-rewrites`.
- Activity selection (FR-P-05, TD-16/X-05) and the first-story trigger (X-22, TD-27) do not exist; `context-confirmation` returns the run (200) and starts nothing.

## 2. Decisions (SRS-cited)

- **T2D-D1 OD-18c precondition: the 202 change applies (l.1666, FR-P-04).** Evidence from the Android client: the only call is `confirmStoryRunSubjectV1` (`ParentApi.ts:204-213`); the shared `request()` accepts any `response.ok` (l.499-507) and never compares the status with 200; the screen reads only `story_run_id`, `understanding_revision` and `decision` from the body (`useParentController.ts:1036-1046`), which stay unchanged; the lifecycle path in `liveRunOrLifecycleError` keys on the body, not the status. The `status: 200` literals are mock fixtures (`tests/parentApiI2Contract.test.ts:232`, `parentStoryRunProjectionContract.test.ts`), not server behaviour. The web client has no caller; the older `apps/mobile` client targets an unmounted path. **Conclusion: no dependence on 200; the change is made.** Side finding for the FE owner (not caused here): the screen rejects a corrected-subject answer because it compares the returned revision (N+1) with the revision it sent (`useParentController.ts:1039`); that mismatch exists at HEAD.
- **T2D-D2 subject-confirmation (l.1666, P-07).** Status 202 on both paths and for the replay of a purged run (lifecycle envelope under the route's normal status). Body: the four existing fields unchanged, plus additive `run_revision` and `job` (`null` until Q-J, see T-2b section 6). Key, revision and 409 behaviour unchanged (`PARENT_UNDERSTANDING_REVISION_STALE` and `PARENT_SUBJECT_REVIEW_NOT_ACTIVE` become `STALE_REVISION` and `INVALID_STATE_TRANSITION` with `current_version` only if the review asks; today the story envelope maps unknown codes to a generic message, which is Q-2d-4). **Edit semantics are Q-2d-1:** default A keeps HEAD (the correction is recorded as revision N+1 and confirmed at once; no VLM rerun); the SRS wording (l.394, l.1413: an edit starts a new VLM job and the run returns to `INPUT_PROCESSING` then `SUBJECT_REVIEW`) is variant B, which changes the Android screen into a two-step flow.
- **T2D-D3 story-rewrites (l.1668, FR-P-07 l.516, l.1699, l.866).** `POST /v1/story-runs/{run_id}/story-rewrites` in `routers/parent_story_inputs.py`; key required 1-128; body `RewriteStoryRequestV1` (`extra=forbid`): `expected_story_revision` (1-3, the `revision_no` of the current draft), optional `hint` (1-400 chars), optional `expected_story_sha256` (checked when sent). Success 202 `ParentStoryRewriteAcceptedV1 {request_id, story_run_id, story_revision_no, run_revision, run_state "SCRIPT_GENERATING", job}`. Errors: 404 (role, run); 409 `STORY_REWRITE_LIMIT_REACHED` (four revisions exist: first story plus three rewrites), `STALE_REVISION` (revision or hash differs from the current draft; `current_version` = latest `revision_no`), `INVALID_STATE_TRANSITION` (run not in `SCRIPT_REVIEW`, no first story yet, or a rewrite already generating); 422 `TRANSCRIPT_NOT_CONFIRMED` (T-2c gate) and `SUBJECT_NOT_CONFIRMED`, `PROFILE_CONTEXT_NOT_CONFIRMED` (already raised by the repository). The server derives the understanding revision from the run (not from the client). Receipt: existing operation `GENERATE_STORY_REVISION` (no DDL); replay returns the stored 202; another body with the key is 400 `INVALID_IDEMPOTENCY_KEY`. The old route keeps key 1-200 and its behaviour.
- **T2D-D4 Hint rules (l.1668 "gợi ý tùy chọn có giới hạn và được sàng lọc", FR-AI-12 l.578, BR-36 l.280).** The hint is untrusted data: trimmed, 1-400 characters, no control characters, never concatenated into instructions (it is a separate worker-input field, as today). No hint is allowed (l.1668 says optional): the server then sends a fixed server-owned neutral instruction (Q-2d-3). The versioned child-safety screen of FR-AI-12 does not exist yet; recorded as debt, with the screen port left as the single call site.
- **T2D-D5 Execution (OD-13, l.394).** The route calls `reserve_story_revision` (extended with `expected_story_revision` and a no-hint flag), commits, answers 202, then the T-2b `ParentInputJobRunner` runs `StoryGeneratorPort.generate(worker_input)` through `BackgroundTasks` when `app.state.story_generator` is composed (local fixture adapter keyed by request hash; `None` leaves the run in `SCRIPT_GENERATING` with `job_state QUEUED`, like T-2b). The post-generation logic of `parent_ai.generate_story_revision` (schema validation, lifecycle fact check, hash, `complete_story_revision` or `fail_story_revision`) moves unchanged into `application/services/story_output.py` and both routes call it, so behaviour and the existing late-result tests stay. No Modal call is added; wrapping `ModalStoryFunctionClient` is OD-13.
- **T2D-D6 First-story trigger (X-22, TD-27 fallback).** The SRS names no route (l.1667 returns a snapshot ref only; l.394 allows `STORY_GENERATING` only after subject, context and an activity are chosen, and the activity gate X-05/TD-16 is not built). The implicit trigger after `context-confirmation` is therefore not built. Fallback applies: `story-revisions` stays the only first-story route, `story-rewrites` is added beside it, nothing is removed. Recorded for the review (R-5: the story stage lacks the activity precondition FR-P-05 requires).
- **T2D-D7 Guard, P-12(c) (CV-5, l.864-865).** `_require_parent` in `parent_ai.py` answers the uniform 404 `RESOURCE_NOT_FOUND` for no identity, inactive identity, issuer mismatch and a non-Parent role, still before `_require_modal_dev()` (an out-of-scope caller never learns the provider configuration). OD-18b is gated on the Android check; the T0.9 plan review re-ran it and found no client branch on 403 for these families, and `PARENT_ROLE_REQUIRED` occurs nowhere outside this file (grep of mobile, web, tests). `/sketch-guides` follows (same helper). No source-plan row assigns this guard to a task; the coordinator ruled it into T-2d, and the evidence note records it as P-12(c).
- **T2D-D8 Envelope, P-35.** The new route and subject-confirmation use the M2 story envelope automatically (`/v1/story-runs*`). `/sketch-guides` keeps the raw `detail` body (dev-only, PARENT_SKETCH_GUIDE is unscheduled, X-06 family); `app.py` is edited only to add story-envelope messages for `STORY_REWRITE_LIMIT_REACHED`, `TRANSCRIPT_NOT_CONFIRMED`, `SUBJECT_NOT_CONFIRMED`.
- **T2D-D9 Legacy routes stay (P-06b, P-08a).** `drawing-understandings` is removed only once Android has moved; it has not (section 1), so P-06b is **not done in v3** and stays as an open row (the old route keeps answering). `story-revisions` stays (D6).
