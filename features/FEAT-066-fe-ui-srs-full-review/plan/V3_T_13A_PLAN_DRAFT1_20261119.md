## 1. HEAD facts (verified)

- Parent cancel/delete: `_accept_lifecycle_command` (`parent_story_repository.py:460-645`): owner lookup `FOR UPDATE` (404), replay receipt, revision (cancel only, 409 `STALE_REVISION` with `current_version`), state (409 `INVALID_STATE_TRANSITION`; `CANCEL_ELIGIBLE_STATES`, `DELETE_ELIGIBLE_STATES` = COMPLETED/FAILED/ABANDONED in `story_run_lifecycle.py`), then five writes: run to `DELETE_PENDING` (lock released, revision and version +1), Parent aggregate row, outbox event, accepted audit row, receipt (status 202, content-free projection body). Routes `cancel_parent_story_run` (202) and `delete_parent_story_run` (202) call `_require_parent` first, then `parse_idempotency_key`.
- Every row written there is `PARENT_ACCOUNT` scoped with `organization_id=None` (`_upsert_parent_aggregate`, outbox, audit, payload `reason_code` `PARENT_CANCEL_REQUESTED`/`PARENT_DELETE_REQUESTED`). The Core tables accept `ORGANIZATION` only with `organization_id` NOT NULL and `owner_scope_ref` NULL or equal to it.
- **The purge pipeline is Parent-only** (not stated in the plan): `be1_lifecycle_consumer.py:359` (`scope.kind != PARENT_SCOPE_KIND` gives `LIFECYCLE_EVENT_INVALID`), `:839-846` and `:886` (request and exception audit rows written with `organization_id=None` and the Parent kind); `story_lifecycle_store.py` lines 127, 254, 277, 297, 320, 426, 454, 467 filter or write `PARENT_SCOPE_KIND`. `core_lifecycle_store.py` and `LifecycleScope` (`core_foundation.py:222`, kinds `PARENT_ACCOUNT` and `ORGANIZATION` valid) are already scope-generic (they match `owner_scope_kind == scope.kind and owner_scope_ref == scope.ref`). `be1_data_lifecycle_requests` is `ORGANIZATION`-capable (frc08 migration).
- Without the worker part a Teacher cancel would end with an event the consumer refuses and a run that stays `DELETE_PENDING` for ever, which does not meet FR-C-08 ("xóa nội dung liên kết, báo tiến trình purge").
- Owner harness for the worker: `integration/test_frc08_lifecycle_postgres.py` (skipped unless `FRC08_DATABASE_URL`; `tools/run_be1_lifecycle_consumer.py` allow-list: database name contains `frc08`, port not 5432/5433, loopback S3 endpoint and a bucket containing `frc08`). The goal's containers satisfy it (PostgreSQL 55458, S3Mock 59458, bucket name with the task tag).

## 3. Route and contract table

| Route | Actor | Request | Success | Errors |

| `POST /v1/story-runs/{id}/cancel` | Parent owner or current class Teacher | body `{expected_revision}`; header `Idempotency-Key` | 202 lifecycle envelope (content-free), unchanged | 400 `INVALID_REQUEST`/`INVALID_IDEMPOTENCY_KEY`; 404; 409 `STALE_REVISION` (+ `current_version`), `INVALID_STATE_TRANSITION`; 503 store unavailable |
| `DELETE /v1/story-runs/{id}` | same | header `Idempotency-Key`, no body | 202 lifecycle envelope | 400; 404; 409 `INVALID_STATE_TRANSITION`; 503 |

No new route, no schema change, no new error code; the catalog entries only change the actor text of `purpose`. Keys: existing receipts (`story.command_receipts`, operations `CANCEL_RUN`, `DELETE_RUN`). Revisions: `story.runs.revision`; no ETag (C-D7 story family).

## 4. State machine (unchanged, now reachable by the Teacher)

`CANCEL_ELIGIBLE_STATES` (not COMPLETED/FAILED/ABANDONED/DELETE_PENDING/DELETED) -> `DELETE_PENDING` -> `DELETED` (worker). `DELETE_ELIGIBLE_STATES` (COMPLETED, FAILED, ABANDONED) -> `DELETE_PENDING` -> `DELETED`. Transitions out of `DELETE_PENDING` happen only in the worker.
