## 3. story-rewrites (l.1668, FR-P-07 l.516, l.1699, l.866)

- **T2D-D3 Route.** `POST /v1/story-runs/{run_id}/story-rewrites` in `routers/parent_story_inputs.py`; key 1-128; body `RewriteStoryRequestV1` (`extra=forbid`): `expected_story_revision` (`ge=1`, `le=4`: the `revision_no` of the current draft, which is 4 after the third rewrite), optional `expected_story_sha256`, optional `hint` (1-400). **Order of checks:** body validation; role guard (404); key; run lookup; purged run (fresh command 409, replay returns the lifecycle projection); replay; run state `SCRIPT_REVIEW` and a first story in `DRAFT` or `FAILED` else 409 `INVALID_STATE_TRANSITION`; **`len(revisions) >= 4` gives 409 `STORY_REWRITE_LIMIT_REACHED` before the stale check** (so a client at the limit learns the real reason); then revision or hash mismatch gives 409 `STALE_REVISION` with `current_version` = latest `revision_no`; then gates: `PARENT_SUBJECT_CONFIRMATION_REQUIRED` is mapped to **422 `SUBJECT_NOT_CONFIRMED`** (new message), context to 422 `PROFILE_CONTEXT_NOT_CONFIRMED`, transcript to 422 `TRANSCRIPT_NOT_CONFIRMED` (T-2c). Other repository codes map: `PARENT_STORY_RUN_NOT_READY_FOR_SCRIPT` and `PARENT_STORY_REWRITE_NOT_ALLOWED` to `INVALID_STATE_TRANSITION`. The server derives the understanding revision from the run.
- **T2D-D5 Receipt and replay (R1 D2).** New repository method `reserve_story_rewrite` stores the receipt **already `FINAL`** in the reservation transaction: status 202, body = the 202 body (`story_revision_no`, `story_revision_id`, `run_revision`, `run_state "SCRIPT_GENERATING"`), operation `GENERATE_STORY_REVISION`. The reservation carries `receipt_id=None`, so `complete_story_revision` and `fail_story_revision` skip the receipt update for it; the legacy route and its tests are unchanged. Replay (same key and body, including while the run is still `SCRIPT_GENERATING` and after completion) returns the stored 202; the same key on the legacy and the new route is 400 `INVALID_IDEMPOTENCY_KEY` (same operation, different fingerprint).
- **T2D-D6 Hint (l.1668, FR-AI-12 l.578, BR-36 l.280).** Untrusted data: trimmed, 1-400, no control characters, a separate worker field, never concatenated into instructions. No hint is allowed: the server sends the constant `REWRITE_NEUTRAL_INSTRUCTION_V1` (in code, versioned `rewrite-neutral.v1`, part of the receipt fingerprint, default text "Hãy viết lại câu chuyện theo một cách khác, giữ nguyên chủ thể và ý tưởng của người lớn."; wording to be confirmed by the owner, tests pin the default). The explicit no-hint flag lifts the repository refusal at `:1272`. The versioned child-safety screen (FR-AI-12) does not exist: recorded debt, one call site.
- **T2D-D7 Execution (OD-13, l.394).** After the 202, the T-2b runner (own session, `BackgroundTasks`) runs `StoryGeneratorPort.generate(worker_input)` when `app.state.story_generator` is composed (fixture adapter keyed by request hash); `None` leaves the run `SCRIPT_GENERATING` with `job_state QUEUED` (the new route writes `QUEUED`; the runner sets `RUNNING`); cancel works. The post-generation logic of `parent_ai.generate_story_revision` moves unchanged into `application/services/story_output.py` and both routes call it; it must return the same fields to the legacy route (`story_sha256`, `review_required`, `model`) and the late-result tests stay unchanged. `run_state` is the documented extension `SCRIPT_GENERATING` (l.394 lists `STORY_GENERATING`; `EXTENSION_RUN_STATES`). No Modal call is added.
