## 1. Changes to Draft 1

- **Asset handle (R1 F-01, ruling 1).** T-2a returns the opaque handle `upl_{upload_id}` as `asset_ref`; the object key never leaves the API (SRS l.1692). The request body keeps one field `asset_ref`, but only the `upl_` form passes validation (400 `INVALID_FORMAT` otherwise). The server finds the completed session by that id (owner, purpose, target, organization, state `COMPLETED`, scan verdict `CLEAN`), resolves the key with `resolve_asset_key` and reads the object through the storage port. Draft 1 §1 "Assets" (asset ref equals the key; a small read helper in T-3b) is withdrawn.
- **Parser deadline, cap and locks (R1 F-03, ruling 2).** TD-15 stands as a recorded technical decision with its deviation from SRS l.1940-1941 (parser in a resource-limited worker): the parse runs in a bounded thread of the API process, with a wall-clock deadline, a process-wide concurrency cap and a queue wait that answers 503. Order of work: authorise and snapshot with no row lock, release the connection, read and verify the object, parse, then lock the occurrence and the upload session, re-check, write, commit.
- **Text hazards (R1 F-02, ruling 3).** The parser normalises its text (NUL and other control characters removed, lone surrogates replaced); the service refuses text that is still not storable. Every parser rejection is answered on the request with no row and no job.
- **Job read rule (R1 F-04, ruling 5, T0.4-DEBT-1).** The `LESSON_SOURCE_DOCUMENT` kind is registered through a port (`SourceDocumentClassLookup`); the rule needs the `teacher` role for the exact class (new `ActorMembership.class_roles`), and an actor the rule accepts is read as Teacher whatever the union of organization roles says. The inline job is recorded through a port (`InlineJobRecorder`).
- **Inline policy (R1 F-03 item 4).** `lesson.inline.v1`, one attempt, status `INLINE_NO_RETRY` (not `PROPOSED`).
- **Envelope (R1 F-05).** All new top-level codes get Vietnamese messages: `INVALID_FILE_CONTENT`, `OCR_NOT_SUPPORTED`, `ENCRYPTED_DOCUMENT_UNSUPPORTED`, `DOCUMENT_PAGE_LIMIT_EXCEEDED`, `DOCUMENT_TEXT_LIMIT_EXCEEDED`. The "stale hash 409" of the source plan P-18a belongs to the T-3d confirm, not to this route (a changed object is 422 `UPLOAD_CHECKSUM_MISMATCH`).
- **Parser limits (R1 F-06).** A DOCX has no page count at HEAD (`page_or_slide_count` is NULL), so the 100-page limit is enforced for PDF and PPTX only. A document with some text and some scan or blank pages is accepted and marked (`OCR_NOT_SUPPORTED_PAGES`, derived by the service from the page count and `page_coverage`); only a document with no text at all is refused.
- **FE-projected OpenAPI (ruling).** The five operations join the contract catalogue (`MOUNTED_OPERATIONS`); they are not added to `SRS_V22_INCLUDED_OPERATIONS`, and neither is `GET /v1/jobs/{job_id}`.
