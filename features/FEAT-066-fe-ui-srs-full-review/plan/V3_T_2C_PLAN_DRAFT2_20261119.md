## 2. Decisions (SRS-cited)

- **T2C-D1 Idea route (l.1665, FR-P-03 l.512, BR-23 l.267, l.1413).** `POST /v1/story-runs/{run_id}/idea`, key 1-128, body `AddRunIdeaRequestV1` (`extra=forbid`): `expected_run_revision` (required), then either `text` (1-500) and/or `audio_ref` (`upl_...`), or `transcript_correction {base_revision, text 1-500}`; mixing the groups, or none, is 400 `INVALID_REQUEST`. Allowed states `INPUT_PROCESSING`, `INPUT_REVIEW`, `SUBJECT_REVIEW`, else 409 `INVALID_STATE_TRANSITION`; stale revision 409 `STALE_REVISION` with `current_version`. A text or audio submission writes input revision N+1 by **copying forward every column** (drawing, context and its confirmation, voice, typed idea) and replacing only what was submitted; a correction writes only a transcript revision. **A fresh command on a purged run is 409; a replay returns the lifecycle projection** (DTR 6.5, model after `confirm_subject`); response model is a union with `ParentStoryRunLifecycleEnvelopeV1`. Receipt `SUBMIT_IDEA`, scope `STORY_RUN/{id}`.
- **T2C-D2 Audio admission (l.982, BR-23, l.1942, l.1664).** `audio_ref` is resolved with `resolve_completed_upload` (purpose `RUN_AUDIO`, completed, this run, caller scope, `CLEAN`); any miss is the uniform 404. Size at most 20,000,000 bytes (declared and real), duration at most 120 s read from the bytes by `infrastructure/media_validation/audio_duration.py` (WAV by stdlib `wave`; MP4/M4A by `mvhd`; no decoder). Over a limit: 413 `AUDIO_TOO_LARGE`; unreadable or non-PCM WAV: 422 `UPLOAD_CONTENT_MISMATCH`. The MP4 parser covers `moov` after `mdat`, 64-bit sizes, size 0, nesting depth cap, `mvhd` v0 and v1, timescale 0, duration overflow, and a cap on scanned bytes (hostile-file tests). Upload policy: `RUN_AUDIO` enabled for `audio/wav` and `audio/mp4` (Q-2c-1); signature table gains `audio/mp4` (bytes 4-8 `ftyp`); `ParentRunAudioResolver` plus `ensure_accepting_audio` (states above); `AUDIO_TOO_LARGE` message. A completed same-run `RUN_AUDIO` session offered to `/assets` answers 415 (T-2b D2), tested here.
- **T2C-D3 ASR step behind a port (OD-13, l.731).** `SpeechTranscriberPort.transcribe(request) -> result` (text, language, model revision, config hash, optional timing); `FixtureSpeechTranscriber` answers only for an explicit mapping of audio SHA-256 to text. `app.state.speech_transcriber` defaults to `None`: the transcript stays `PENDING` and the run waits (cancel works). When composed, the T-2b runner (own session, `BackgroundTasks`) completes it. ASR text is untrusted and is not safety-screened (FR-AI-12 l.578 policy does not exist): recorded debt; the text reaches only the adult's transcript read, and the gate (D6) keeps unconfirmed text from the story worker. Retention maximum is open (OI-06); BR-23 and l.1472 (keep until run deletion) are implemented.
- **T2C-D4 Transcript confirmation, TD-04 (l.512, l.1713, l.871, l.1726, l.1829).** `POST /v1/story-runs/{run_id}/transcript-confirmation` (route name candidate, follows `subject-/context-/script-confirmation`), key required, body `{expected_transcript_revision, transcript_sha256, confirmed: true}`, 200 `ParentTranscriptConfirmationV1 {request_id, story_run_id, transcript_revision, state "CONFIRMED", run_revision, run_state}`. Hash = SHA-256 of the effective text (corrected text, else raw, UTF-8). Wrong revision or hash: 409 `STALE_REVISION` (`current_version` = latest transcript revision). State not `NEEDS_CONFIRMATION`: 409 `INVALID_STATE_TRANSITION`; already confirmed same revision and hash: 200 no-op. Effective text plus typed idea (one space) over 500: **400 `INVALID_REQUEST` with `field_errors [{field "transcript", code "TOO_LONG"}]`** (§9.8 puts `INVALID_REQUEST` under 400; no silent truncation). **Supersede rules:** (a) a correction supersedes both an unconfirmed and a confirmed row of the same voice asset in the same transaction; (b) order: update the old row to `SUPERSEDED` first, then insert (the partial unique indexes are checked per statement); (c) correcting a confirmed transcript from `SUBJECT_REVIEW` returns the run to `INPUT_REVIEW`; (d) the gate and the story input read the **latest non-superseded** revision of the current voice asset and require `CONFIRMED`. A correction is also allowed on a `FAILED` row (no ASR text exists; the adult types it). Purged-run rule as D1.
- **T2C-D5 Transcript read (l.780, l.1164, l.1707 "rà soát transcript" Parent row, BR-34).** `GET /v1/story-runs/{run_id}/transcript`: 200 `ParentRunTranscriptV1 {story_run_id, transcript_revision|null, state NONE|PENDING|NEEDS_CONFIRMATION|CONFIRMED|FAILED, origin, text, transcript_sha256, language, error_code, run_revision}`, owner only, uniform 404 (Manager and Admin included, l.1616), `Cache-Control: private, no-store`; text never in logs, audit or error bodies (l.942, NFR-03). Candidate shape (TD-04 names only the confirm command). `ParentStoryRunResponseV1` is unchanged.
- **T2C-D6 State machine and gate (l.394, l.871).** One function `settle_input_state(run)` is called by every writer (attach, `/idea`, runner completion, transcript confirm, `record_understanding`). Let D = drawing on the current input; U = an understanding whose run input has the current drawing; T = state of the latest non-superseded transcript of the current voice asset (none, PENDING, NEEDS_CONFIRMATION, FAILED, CONFIRMED). Rules in order: not D gives `INPUT_PROCESSING`; VLM outstanding (D, not U, `job_state` QUEUED or RUNNING) or T = PENDING gives `INPUT_PROCESSING`; VLM recoverable failure (D, not U, `FAILED`) gives `INPUT_REVIEW` (T-2b's `INPUT_PROCESSING/FAILED` moves here; retake eligibility becomes `SUBJECT_REVIEW` or `INPUT_REVIEW`); voice with T = NEEDS_CONFIRMATION or FAILED gives `INPUT_REVIEW`; U gives `SUBJECT_REVIEW`; else `INPUT_PROCESSING`. It only acts in `INPUT_PROCESSING`, `INPUT_REVIEW`, `SUBJECT_REVIEW`. `record_understanding` keeps accepting only `INPUT_PROCESSING` (settle holds the run there while a VLM job is outstanding) and then settles. `confirm_context` refuses `INPUT_REVIEW` (409). `job_state` on the run stays the VLM step; the ASR step is read through the transcript. **Gate:** `reserve_story_revision` (old and new story routes) refuses 422 `TRANSCRIPT_NOT_CONFIRMED` when the current input has a voice asset and its latest non-superseded transcript is not `CONFIRMED`, and builds the worker idea from typed idea plus that confirmed text (at most 500). The transcript is found by `(run_id, source_asset_ref)`, **not** by `run_input_id`, so a retake (which copies `voice_*` forward) cannot bypass the gate.
- **T2C-D7 Lifecycle (BR-23, BR-26 l.270, l.1472).** The purge store lists `transcript_revisions` child ids, deletes them before `run_inputs`, and `assets_referenced_by_other_runs` includes `voice_asset_ref`; a test proves plan and sweep leave no audio or transcript.
- **T2C-D8 Deviation from the WP-2 row (Q-2c-2).** Audio attaches through `/idea` (l.1665 gives it an audio ref and the owner-equals-run rule is enforced there), not through `/assets` (l.1664 says "tranh/audio"). Recorded in the evidence note as a deviation from the source-plan row.
- **T2C-D9 Envelope.** Uses T-2b D10 (`current_version`, `field_errors`); T-2c adds messages for `AUDIO_TOO_LARGE`, `TRANSCRIPT_NOT_CONFIRMED`, `UPLOAD_*` and `STORAGE_UNAVAILABLE` if T-2b has not.
