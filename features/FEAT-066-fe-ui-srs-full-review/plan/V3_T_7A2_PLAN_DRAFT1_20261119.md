## 1. HEAD facts

`require_assignment` (`routers/be1_common.py` l.88-156): reads the identity (active, issuer equal to the token, account role `teacher` or `school_manager`), the caller's `be1_organization_assignments` rows with `active = true` in the organization, keeps `teacher`/`guide`/`observer` rows for a Teacher account and `school_admin` rows for a Manager, then keeps only rows that **cover** the class (`class_id IS NULL` or equal). No covering row: uniform 404. A `roles=` filter that removes every covering row: 403 `ACTION_NOT_ALLOWED`. So an org-wide row (`class_id NULL`) of role `teacher` **covers every class** and passes `roles={"teacher"}`. That is the gap.

| Route (HEAD line) | Guard today | Returns |
|---|---|---|
| A09 `GET .../classes/{class_id}/profiles` (`be1_registry.py` l.648) | T-7a `_roster_audience`: only a `teacher` row with `class_id == class` gets fields; Manager gets a count; others 403 | `child_id`, `display_name`, `age_months` |
| A10 `GET .../classes/{class_id}/consents` (l.942) | same `_roster_audience` | `child_id`, `purpose_ref`, state |
| **R1** `GET .../sessions/{session_id}/pilot-profiles` (l.723) | `get_session`, then `roles={"teacher"}` with the session class: **an org-wide `teacher` row passes** | `child_id`, `display_name` |
| **R2** `GET .../sessions/{session_id}/roster` (`be1_sessions.py` l.300) | `get_session`, then `roles={"teacher"}`: **org-wide `teacher` row passes** | `child_id`, `display_name`, `device_grant_id`, groups, turns |
| **R3** `GET .../classes/{class_id}/profiles/{child_id}/portfolio` (`be1_records.py` l.403) | no role filter: **Manager, guide, observer and org-wide rows pass**; then 404 `PROFILE_NOT_FOUND` for an unknown child, else 409 `CONSENT_NOT_EFFECTIVE` | no child fields, but it confirms that a `child_id` exists in the class |

Production data: org-wide rows are written only for `school_admin` (`be1_bootstrap.py` l.52, `platform_admin_accounts.py` l.289); `teacher` rows only by `POST /classes/{class_id}/assignments` (`be1_registry.py` l.408), class-scoped; guide and observer rows have no writer. The gap is defence in depth and SRS fidelity, reachable by seeded data, not by current accounts.

## 2. SRS basis and decisions

Clauses: l.2584-2586 (access matrix, Profile row: Teacher reads "only fields granted after the Teacher accepts the invitation and the class is assigned"; Manager "no profile contents by default"); l.2589 (Occurrence and child media: assigned child/run with a valid grant); l.2594 (permission checks are server-side; losing the assignment invalidates access); l.2602 (roster access needs role, organization, class assignment and an active link or grant); l.541 (FR-T-02: exactly one Teacher is responsible per class); l.543-544 (FR-T-04, FR-T-05: a profile has at most one active class enrollment); l.553 (FR-T-14: access follows the current responsible Teacher; reassignment revokes at once); l.864-865 (403 only when the resource is known to be in the caller's scope; otherwise the one 404 body, no leak of membership or assignment); l.2733 (AC-64, child media only, not cited for profile fields).
