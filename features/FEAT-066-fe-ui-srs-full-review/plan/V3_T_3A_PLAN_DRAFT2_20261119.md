## 1. DDL-A as amended (the text the owner approves by name under OD-01)

Same five tables, same names, no new table and no column beyond Draft 1 section 4; migration `20261119_oc_0001`, parent `20261119_uf_0001` (T-2a), create-only, no branch label. Additions:

- **A1 (pointer).** `lesson.plan_revisions` gets `UNIQUE (plan_revision_id, occurrence_id)` (`uq_plan_id_occurrence`). `lesson.occurrences.approved_plan_revision_id` is a composite foreign key `(approved_plan_revision_id, occurrence_id) -> plan_revisions (plan_revision_id, occurrence_id)`, immediate (not deferrable), `ON DELETE RESTRICT`, MATCH SIMPLE (no check while the pointer is NULL). `lesson.protect_occurrence` also requires the target plan to be `APPROVED` whenever the pointer is set or changed, and an occurrence is born `DRAFT` with no pointer.
- **A2 (plan insert).** `lesson.protect_plan_revision` (INSERT) refuses a plan that is not a `DRAFT` with empty `approved_by/at/superseded_at`; whose four pin columns differ from the occurrence's (all null or all equal); whose document revision belongs to another occurrence or to a `DELETED` document; whose `revision_no` is not head + 1; or whose objectives are not an array of 1-12 strings of 1-1000 characters. UPDATE: content columns immutable; `DRAFT -> APPROVED` fails `LESSON_PLAN_CHECKLIST_REQUIRED` while a `CUSTOM` activity lacks `confirmed_at`; `APPROVED -> SUPERSEDED`; nothing else.
- **A3 (review F-06 details).** Account refs are `VARCHAR(36)`; `created_at`/`updated_at`/`uploaded_at` default `now()`; value CHECKs for every enumerated column and every JSON array/object column (`CASE` form so a jsonb function never raises); SHA-256 hex CHECKs; `extracted_text_hash` equals `sha256(utf-8 bytes)` in the database; `revision_no` = head + 1 enforced by trigger for document and plan revisions; plan activity rules per kind (CUSTOM: title 1-200, description 1-4000 as Draft 1 and the T-3d plan say, no catalog ref; LESSON/CATALOG: catalog ref, object snapshot, hash; `activity_order` 1-24; checklist columns all-or-none and only on CUSTOM); `source_documents.extraction_job_ref` is NOT NULL (the job id exists before the insert); `source_documents` and `document_revisions` get insert triggers (born `EXTRACTED`, born `NEEDS_REVIEW`).
- **Occurrence states (implementation review F-01; SRS §6.1.1 l.396).** Draft 1 invented `PLANNING|PLAN_APPROVED`; DDL-A and the public enum use the SRS names `DRAFT, DOCUMENT_REVIEW, PLAN_REVIEW, APPROVED, SAMPLE_AVAILABLE, SAMPLE_USED, ARCHIVED` (the CHECK allows the whole set so WP-4b needs no change). Mapping: `PLANNING = DRAFT`, `PLAN_APPROVED = APPROVED`; the pointer is NULL exactly in `DRAFT`, `DOCUMENT_REVIEW`, `PLAN_REVIEW` and set in `APPROVED`, `SAMPLE_AVAILABLE`, `SAMPLE_USED`. T-3a creates `DRAFT`; T-3d sets `APPROVED` (its plan text says `PLAN_APPROVED`, to be read as `APPROVED`). `DOCUMENT_REVIEW` and `PLAN_REVIEW` are not set by any v3 route (document and plan review states live in `document_revisions.review_state` and `plan_revisions.state`); the `sample_slot_state` column and the `SAMPLE_*` states overlap and WP-4b must reconcile them.
- **Reserved states.** `occurrences.state = ARCHIVED` and `source_documents.document_state = DELETED` have no route in v3 (the SRS lists none): tests set them by SQL; `ARCHIVED` is not a one-way state.
- **Overloaded column.** For `LESSON` activities `catalog_activity_ref` holds the library `version_activities.activity_id` (REG l.356 keeps it opaque).
- **Consequence recorded.** DELETE is forbidden on all five tables and `extracted_text` is immutable, so a later erasure task (lifecycle "xóa") needs a new migration; `TRUNCATE` of all five tables is the only bulk erasure today.
- `occurrences.revision` is service-incremented and `occurrences.revision` is the ETag source: any WP-4b change to `sample_*` columns must bump it.

## 2. Decisions that change or sharpen Draft 1

- **T-3a-DEC-2 Assignment table (review F-01).** Stage 1 resolves the class row (unknown: 404), then the caller's active teacher-family rows in the class's organization (no valid Teacher identity or no row: 404, the same body as an unknown class). Stage 2 uses rows with `class_id` equal to this class: a `teacher` row proceeds; only `guide`/`observer`: 403 `ACTION_NOT_ALLOWED`; none: **409 `TEACHER_ASSIGNMENT_REQUIRED`**. A row with `class_id` NULL counts for reads (the BE1 convention) but **not** for create (SRS l.775 "Teacher phụ trách hiện tại" is per class; M9-B writes class-scoped rows). Stage 3: class `state <> 'active'`: 409 `INVALID_STATE_TRANSITION`, after stage 2 and after a receipt replay. A Teacher of the organization can tell an existing class from an unknown id (accepted by the source plan).
- **T-3a-DEC-6 Pin (review F-04, F-05).** `lesson_version_ref` is `LessonVersionRefV1 {lesson_id, version_id, content_sha256}`, the Parent flow's shape; `version_no` is stored for lineage and read back as `lesson_version_no` (display only). Default eligibility is fail-closed: same organization as the class, item `ACTIVE`, `moderation_state VISIBLE`, visible to the caller by the `get_lesson` rule, version `APPROVED` (visible but not approved: 409 `INVALID_STATE_TRANSITION`; a hash that differs: 409 `STALE_REVISION`; anything not visible: 404). OQ-3 stays open for the owner (draft pins, library grants, other organizations); loosening later never invalidates stored pins.
- **T-3a-DEC-5 Capacity deviation.** SRS l.1652 says "xác minh sức chứa/phân công". Capacity belongs to X-13 (Billing, deferred, R3): `CLASS_CAPACITY_REACHED` is never returned in v3. Recorded as a deviation, not a remark.
- **Receipts (review F-08).** The success body is small and carries no child or storage data, so it is stored in `response_json` and replayed verbatim with status 201, `Location` and `ETag`. Audit entry `lesson.occurrence.create` (account ref as actor). T-3b/T-3d may adopt the same rule.
- **Limits (review rulings on 50/10/12).** Objectives 1-12 of 1-1000 characters and activities 0-24 are enforced in DDL-A where the database can (array length, element trigger, `activity_order` 1-24); the 50-revisions-per-document cap is a T-3c service rule, not DDL.
- **Resolver (Draft 1 T3A-D8).** Registered in T-3a: `OccurrenceUploadTargetResolver` in `app.state.upload_target_resolver_factories` (set by `mount_all_routers`, a factory already on `app.state` is kept). Only the responsible Teacher resolves; everyone else gets the uniform 404.
- **Envelope.** `/v1/lesson-occurrences` joins the CONV-1 family by a whole-segment rule (`LESSON_OCCURRENCES_BASE`), like the upload base; `TEACHER_ASSIGNMENT_REQUIRED` gets its message here.
