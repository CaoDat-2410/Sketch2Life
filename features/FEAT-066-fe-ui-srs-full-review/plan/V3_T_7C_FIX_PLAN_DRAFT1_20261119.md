## 1. Facts at the tree

- **Fingerprint:** `_profile_fingerprint` (`be1_registry.py:1027`) is `sha256(json{v:1, principal, scope, display_name, age_months, consent_id, if_match})`, stored in `be1_command_receipts.request_fingerprint` (`String(64)`, `CHECK length = 64`, `be1_models.py:76-95`). Created at `be1_registry.py:1316`, compared in `_replayed_profile` (`:1091`, mismatch -> 400 `INVALID_IDEMPOTENCY_KEY`).
- **Receipt rows that carry child-derived data:** (a) create receipt: `request_fingerprint` (name and age in the hash), `response_json.child_id`; (b) move receipt (T-7d): `operation_scope` holds `child_id` (unless hashed), `response_json.child_id`, fingerprint over opaque ids only (no name). Other `be1_command_receipts` writers (class create, assignment, state, lesson, upload, platform admin) hold class names, class ids or adult data, not child data. `be1_session_command_receipts` is session-scoped (not touched).
- **Adjacent finding (out of scope, Q-5):** `parent.command_receipts.request_fingerprint` is a plain SHA-256 over `{display_name, age_months, interests_summary}` (`domain/parent_profiles.py:47,122`; `parent_profile_repository.py:49`) and Parent profiles hold real names by design. Parent delete only sets `DELETE_PENDING` (`parent_profile_repository.py:268-310`); nothing purges those receipts.
- **FR-C-10 deletion path (l.502): does not exist for BE1.** No Teacher profile delete route or worker in `be1_registry.py`, `be1_worker.py` or `be1_lifecycle_consumer.py` (the latter purges Parent StoryRuns, FR-C-08, not profiles). Nothing covers receipts, audit rows (`resource_id` = `child_id`) or outbox events (`payload.child_id`). The SRS says the deleter role "must be decided before real data" (l.502); OD-06 and X-19 keep it open.
- **Rate-limit infra:** (1) `RegistrationRateLimiter` (`auth_registration.py:140`): process-local, bounded LRU, sliding window, constants 5 per 15 min per client host, 429 via `HTTPException(headers={"Retry-After"})`. (2) DB-backed room-code limiter (`be1_sessions.py:92,1223`): 10 per 15 min, HMAC of the source IP, advisory lock, a table, 429 `ROOM_CODE_RATE_LIMITED` without `Retry-After`. (3) `assistance.py` `RATE_LIMITED`. The CONV-1 handler (`app.py:~600`) already turns an `HTTPException(429, detail code RATE_LIMITED, headers Retry-After)` into the envelope with `retry_after_seconds` and echoes the header; `BE1_ERROR_RESPONSES` already declares 429. No generic limiter, no Redis code. SRS l.972 gives 60 per minute per account for authenticated APIs; no number for this gate (X-18: parameters need a benchmark).
- **Settings:** `room_code_hmac_key: SecretStr | None` (min 32 bytes enforced at use, 503 if absent). `Settings` is built once (`get_settings` cache); PG tests mutate `d.settings()` after `create_app()`.

## 2. Decisions (T-7cfix-DEC-n; draft numbers are the coordinator's)

| ID | Decision | SRS |

Key = new `Settings.profile_receipt_hmac_key: SecretStr | None` (`SKETCH2LIFE_PROFILE_RECEIPT_HMAC_KEY`, at least 32 bytes), **never** the room-code key (separation). Staging/production never generate. Never logged: `SecretStr`, never in audit, outbox, receipt, error body or log; `hide_input_in_errors` already on; validator messages never echo it. | BR-34 |
| DEC-3 | Refusals, three layers. **Settings validator:** `real_profile_data_enabled` with `env in {staging, production}` and no key -> `ValueError`; a configured key shorter than 32 bytes -> `ValueError` (any env). **Runtime constructor:** `build_be1_runtime` repeats the staging/production check (defence for a hand-built or mutated settings object) and raises a `RuntimeError`. **Handler:** when the key is absent the handler skips the receipt steps only until it needs them; at the `synthetic` or `real_gate` branch, or when a receipt exists, a missing key is 503 `SERVICE_UNAVAILABLE` (public `PROVIDER_UNAVAILABLE`), never a write. Staging today (flags off, no key) keeps its 409 `SYNTHETIC_PROFILE_CREATION_UNAVAILABLE`. | l.832, OD-06 |
| DEC-4 | Old format: **treated as non-matching, no migration, no legacy fallback.** A stored v1 value is a plain SHA-256 and can never equal a v2 MAC, so `_replayed_profile` answers it with the existing 400 `INVALID_IDEMPOTENCY_KEY` ("key already used for another request"). Why this is not a silent break: T-7c (`34705cbf`) is local and unpushed and the Phase B squash ships v1 and v2 together, so no shared environment ever holds a v1 receipt; only developer databases migrated at `34705cbf` do, and they hold synthetic names. A compare-only legacy fallback is rejected: it keeps the plain-hash code that O-1 removes. Same rule for later key rotation or a v3: old receipts do not match; rotate only in a planned window (no key id column). Recorded as Q-3. | l.1697 |
| DEC-5 | **Purge coverage.** New `purge_child_receipts(db, organization_id, child_id) -> int` in a new `infrastructure/persistence/be1_receipts.py`: deletes `be1_command_receipts` rows of the organization whose `response_json->>'child_id'` equals the child (covers create and move receipts, including a hashed move scope). Unit and PG tested, **not wired** to any route: the FR-C-10 deleter role and route are OPEN (l.502, OD-06, X-19). Recorded gap, exactly: (i) no delete route exists; (ii) `be1_audit_entries.resource_id` and outbox `payload.child_id` keep the opaque id after a purge (retention of audit is not decided; BR-34 allows metadata only); (iii) `parent.command_receipts` (adjacent finding). | l.502, l.354 |
| DEC-6 | **Limiter** (`interfaces/http/rate_limit.py`, new): `SlidingWindowLimiter`, process-local, thread-safe, injectable clock. Keys are `(operation, account)` and `(operation, ip)` only, never child id, consent id or content (NFR-12 l.637). Operation = `profile_create_real_gate`. Account = `principal.subject`; IP = `request.client.host` (forwarded headers ignored, as the room-code rule in `backend/README.md`; behind a proxy the IP bucket is coarse until a trusted-proxy boundary exists). Per call it checks both buckets and records in both only when both allow; on refusal `Retry-After` = whole seconds until the oldest hit of the tightest bucket leaves the window (at least 1). Bounded memory: one LRU `OrderedDict` per dimension capped at 1024 keys, each deque at most its limit (the registration limiter's pattern). Defaults (provisional, X-18): **5 attempts per 60 s per account, 20 per 60 s per IP** (the IP figure is the l.973 unauthenticated bucket). Held on `Be1Runtime.profile_gate_limiter` (default factory) so tests inject small limits. | NFR-12, FR-O-06, l.972-973 |
| DEC-7 | **Where it applies.** Only the real-data gate (`_refuse_real_profile`), charged **first** (before the consent lookup, so id probing is limited too), after authorization, replay, stale, state and mode checks: a stranger still gets the uniform 404 and never sees 429; a stale or read-only request is not charged. On refusal: `db.rollback()` (releases the class `FOR UPDATE`), then `HTTPException(429, {"code": "RATE_LIMITED"}, headers {"Retry-After": n})`. The 429 writes no audit row, no receipt, no log line with ids. The synthetic create is **not** limited (Q-4): the general l.972 bucket is X-18 and not built; a single-route bucket would be inconsistent, and the process-local limiter is per worker. | NFR-12 |
| DEC-8 | **Audit bounded, metadata only.** The only audit row of the gate stays `profile.enroll` / `consent` / consent id / `denied_consent_pending` (actor ref, action, resource, result; no name, no child id, no seed, BR-34). With DEC-6 the rows are at most 5 per minute per Teacher account, 20 per minute per IP (per worker). | l.278 |
| DEC-9 (O-3) | Recorded decision: **create does not bump the class revision.** SRS l.1651 says only "expected class revision", l.1699 gives `STALE_REVISION` to an old request, NFR-05 (l.630) asks DB invariants for enrollment; none says create bumps it, and two creates under one revision both succeed (the token guards state, assignment and move). Consistent with T-7c-DEC-2 and TD-28; a one-line flip stays available. No code change. | l.1651, l.1699, l.630 |

## 6. Rollback

One commit, code and tests only; revert it to return to T-7c (v1 fingerprint). No data migration to undo: v2 receipts written meanwhile would be non-matching under v1 and answer 400 on replay, the same rule as DEC-4. The new setting is optional (unset in local/test). The limiter is in memory (nothing persisted).

## 7. Risks

1. **Per-process limiter:** several workers multiply the limits and a restart resets them; acceptable while the real gate only refuses and is off by default; a shared store (Redis per l.608, or a DB table needing DDL) is X-18.
2. **Generated local key:** replays across a restart or between workers get 400; documented, set the key to avoid.
3. **Key loss or rotation** invalidates every open replay (DEC-4 rule); no key id exists.
4. **Hot-file collision:** T-7a2 edits `be1_registry.py` and `be1_common.py` now; apply after its commit.
5. **Existing PG tests** with many gate attempts per runtime could hit the default 5; they inject a roomy limiter.
6. **Behind a proxy** every client shares one IP bucket (20 per minute) until a trusted-proxy boundary exists.
7. The purge helper is dead code until the FR-C-10 path exists; it is kept because it makes the gap exact and testable.
