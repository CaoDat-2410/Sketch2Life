## 2. Decisions

| ID | Decision | SRS basis |

| D2 | **Order:** actor (404), key (400), locked owner lookup **with the assignment re-check** (404; the port reads the assignment row `FOR SHARE` when the run row is locked, so a later revoke serialises behind the command), replay (stored 202), class state (D7), revision (409 `STALE_REVISION` + `current_version`), state (409 `INVALID_STATE_TRANSITION`). A former Teacher replaying an old key gets 404. | l.1697, l.1699, FR-T-14 |
| D3 | **Rows for a Teacher run** (same transaction): run to `DELETE_PENDING`; aggregate, outbox, audit with `owner_scope_kind='ORGANIZATION'`, `organization_id=run.actor_scope_ref`, `owner_scope_ref` the same id; audit `actor_ref` = principal digest; `reason_code` `TEACHER_CANCEL_REQUESTED` / `TEACHER_DELETE_REQUESTED`; receipt under the **command scope** of T-4a1 D5 (per principal). The lookup uses the **owner scope** (T-4a1 `owner_predicate`), never the principal digest. | FR-C-08 |
| D4a | **Worker parity, Story and BE1 side:** the eight Story-store sites and the three consumer sites take the run's own kind; for `ORGANIZATION` write `organization_id=scope.ref` on the lifecycle request, aggregate, audit, exception audit and reconciliation-event rows; Parent rows stay `organization_id=None` byte for byte. | FR-C-08, DTR Draft 6 |
| D4b | **AI-Jobs notice (P1 fix):** add `LifecycleNoticePort.record_lifecycle_notice(*, notice_id, scope: LifecycleScope, story_run_ref, reason_code)`; `record_parent_notice` stays (delegates for the Parent kind, behaviour unchanged). The best-effort cancel of AI jobs (UC-11 l.1522) is exact at `applied_count=0` today because no Teacher run can own a job before T-4b2; T-4b2 must add the job match (subject ref = run ref) to the same recorder (hand-off H2). | FR-C-08, UC-11 |
