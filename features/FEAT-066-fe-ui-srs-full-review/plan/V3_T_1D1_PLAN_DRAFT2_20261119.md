Date 2026-11-21. Goal v3b, T-1d1 (WP-1 T-1d scope). Supersedes Draft 1 (`V3_T_1D1_PLAN_DRAFT1_20261119.md`, written before T-1a, T-1b, T-2c and T-2d landed). ## 1. Facts re-verified (and Draft 1 corrections)

- F1 `story.runs` has `adult_wait_started_at`, `last_meaningful_activity_at`, `finished_at` and `current_video_generation_id`; `ck_story_run_state` has 18 values including `ABANDONED`, `VIDEO_READY`, `SAFETY_BLOCKED`. `DRAFT` and `STORY_GENERATING` are not stored by any code or allowed by the CHECK ("added by whoever first writes them"). There is no `wait_columns` helper; Draft 1 proposed one.
- F2 T-1a and T-1b write the wait columns inline (`advance`, `_reject`, `begin_intent`, `_move_run`); the Parent run repository (`parent_story_repository.py`, the hot file) never writes `adult_wait_started_at` or `last_meaningful_activity_at`. Audit of its 19 `update(story_runs)` sites: every one bumps `updated_at` (the `_apply_settle` helper is always called after a writer that did). The T-2b..T-2d states are `INPUT_PROCESSING` (no drawing yet, or a job), `INPUT_REVIEW`, `SUBJECT_REVIEW`, `PREPARATION_REVIEW`, `SCRIPT_GENERATING`, `SCRIPT_GENERATION_UNKNOWN`, `SCRIPT_REVIEW`.
- F3 `INPUT_PROCESSING` with `job_state` NULL is the draft of the SRS (a run starts there and the adult must still attach a drawing). With a drawing job, or a voice transcript in `PENDING` (the ASR job is mirrored only by `story.transcript_revisions`), the state belongs to the AI.
- F4 T-1a has no deadline sweep and no `deadline_at` column; the six hours are `accepted_at` + 6 h. `StoryVideoProgressService.apply` (compare-and-set `advance` to `FAILED`, then `_close_compute`: settle when the work started, release otherwise) is the one way to end a generation, and `FAILED` frees the lock.
- F5 The lock is `active_owner_parent_account_id` (partial unique index). `ABANDONED` and `COMPLETED` are in `DELETE_ELIGIBLE_STATES`, not in `CANCEL_ELIGIBLE_STATES`, and not in `PURGE_STATES`: a closed run is deletable, never purged by the closeout.
- F6 Existing Parent runs already sit in wait states; the first sweep after deployment can close many old synthetic runs at once (OD-06, synthetic only; recorded).

## 2. Decisions

| ID | Decision | Basis |
|---|---|---|
| T-1d1-DEC-1 | **Wait predicate**, pure in `domain/story_run_closeout.py`: `VIDEO_READY` ends `COMPLETED`; `DRAFT`, `INPUT_REVIEW`, `SUBJECT_REVIEW`, `PREPARATION_REVIEW`, `SCRIPT_REVIEW`, `SAFETY_BLOCKED` end `ABANDONED`; `INPUT_PROCESSING` ends `ABANDONED` only with `job_state` NULL and no `PENDING` transcript. A run whose `job_state` is `QUEUED`, `RUNNING` or `AWAITING_RECONCILIATION` is never closed. `VIDEO_ADMISSION_PENDING`, `VIDEO_QUEUED`, `VIDEO_GENERATING`, `VIDEO_SAFETY_VALIDATING`, `SCRIPT_GENERATING`, `SCRIPT_GENERATION_UNKNOWN`, `STORY_GENERATING` and the closed or purged states are never closed. `SAFETY_BLOCKED` is read as needing the adult in every case (its exits today are cancel and delete). | l.394, l.503 |
| T-1d1-DEC-2 | **Idle clock** = the latest of `updated_at`, `adult_wait_started_at`, `last_meaningful_activity_at` (NULL ignored). The video path writes the last two; the Parent repository bumps `updated_at` on every effective write (F2) and never the others, so no edit to that hot file is needed ("the Parent repository may never write the wait columns": decided, no `wait_columns` helper). Reads, polling, push receipts and playback tokens write no run row and never move it. A refused admission already sets `adult_wait_started_at` = now at the refusal (T-1a `_reject`), so the next closeout is 168 h later. The clock can only be later than the strict SRS clock when a non-adult write bumps `updated_at`; it is never earlier. Due when `now - idle_since >= 168 h` (inclusive). | l.394, l.503 |
| T-1d1-DEC-3 | **Closeout effect**, one transaction per run: `run_state` to the target; `active_owner_parent_account_id` NULL; `finished_at` = `now`; `adult_wait_started_at` NULL; `retryable` false; `revision` and `version` +1; `updated_at` = `now`. Content, generations, assets and receipts are untouched (kept until the user deletes the run); no outbox event, no audit row, no purge, no notification (FR-C-11 asks for none, and a delivery failure may never block the closeout). | l.503, l.394, FR-C-08 |
| T-1d1-DEC-4 | **Concurrency**: listings are bounded read-only prefilters ordered by the clock (oldest first); the close is `SELECT ... FOR UPDATE SKIP LOCKED` on the run row (a row a live command holds is skipped, never waited for), every condition is re-checked under the lock with the pure rules, then a compare-and-set on the locked `revision` and `run_state`. A cancel, confirm, complete or second worker either loses cleanly or makes the row skip. Idempotent: a closed run is no longer a candidate. | l.503 |
| T-1d1-DEC-5 | **Generation deadline**: a generation in `ACCEPTED`, `QUEUED`, `GENERATING`, `TECHNICAL_VALIDATING` or `SAFETY_VALIDATING` with `accepted_at + 6 h <= now` is failed through the T-1a `StoryVideoProgressService.apply` (`safe_failure_code` `VIDEO_DEADLINE_EXCEEDED`): generation `FAILED`, run `FAILED`, lock released, compute reservation settled (started) or released (not started), the quota unit not refunded (no port exists for a refund and l.596 says an admitted unit is never refunded). `ADMISSION_PENDING` is outside it. Listing rows of purged runs are skipped (the cancel path owns them). | l.395, l.503, l.573 |
| T-1d1-DEC-6 | **Entry point**: `StoryRunCloseoutService.run_once(now=None, *, batch_size=50)` (1..500) returns `CloseoutReport(completed, abandoned, deadline_failed, skipped, errors)`. `now` is the test hook (aware instant; default the clock). One row failing is counted and never stops the batch. `build_story_run_closeout(session, adapters)` composes it. **Nothing schedules it**: the periodic runner slice (D-066-73 PD-9a) calls it; recorded. Only `PARENT_ACCOUNT` rows are read (the Teacher owner kind is a DDL-B2 seam). Logs carry counts only (BR-34). | l.503, BR-34 |

## 3. Contract, authorization, FE

No route, no response change, no catalog change. No principal: a system job with no request key. The only public effect is the run state a client reads (`COMPLETED`, `ABANDONED`, `FAILED`) and `can_delete` from the existing summary capabilities. FE: a run can now arrive at `ABANDONED` or `COMPLETED` without a user command and a `FAILED` run can carry `error_code` `VIDEO_DEADLINE_EXCEEDED`.

## 5. Tests

Unit: the predicate over every public state and job state, the clock helpers and the exact 168 h and 6 h boundaries, the service over a fake store (counts, injected instant, one failing row, a failing listing, bounds, naive instant refused, log without ids), a source scan that every `update(story_runs)` site of the Parent repository bumps `updated_at` (guards DEC-2). PostgreSQL (fresh database `frc08_v3_t1d1_*_be1_acceptance`, `alembic upgrade heads`): every stored state times every job state at exactly 168 h against the pure rules; the boundary at 167 h 59 min 59 s and 168 h for each wait state; markers and the latest wins; effects (lock free and a new run can take it, content rows intact); a second pass and a second instant change nothing; batch bound and oldest-first order; `INPUT_PROCESSING` draft, attached, running and pending-transcript cases; a non-Parent kind and the purge states untouched; a row held by a live command is skipped and a real `cancel_run` then wins; a command landing after the listing makes the close skip; a closed run refuses cancel and accepts delete; two concurrent workers close each run once; a real refused admission starts a new wait (168 h after the refusal, not after the earlier wait); the deadline through every in-flight stage with a real admission, exact 6 h boundary, one settle or one release, quota reference kept, idempotent; admission pending untouched; a settled generation untouched; the factory without adapters.

## 6. Risks

R1 A first sweep may close many old synthetic runs (F6). R2 A future Parent-repository write that forgets `updated_at` would close early: the source scan guards it. R3 A lost ASR or VLM job (a `PENDING` transcript or a stuck job state) keeps its run open until the T-2d-fix reaper exists: never closed early, recorded. R4 The deadline pass uses `advance`, which stamps `completed_at` with the real clock, so only the selection is on the injected instant. R5 `DRAFT` cannot be stored today; the rule is pinned in the unit test only.
