## 2. Facts verified at HEAD

Router: `backend/src/sketch2life/interfaces/http/routers/be1_registry.py`.

| Route | Handler | Current guard | Result for a Manager |
|---|---|---|---|
| class profiles | `list_profiles` (l.502) | `require_assignment(db, principal, org, class_id=class_id)` at l.508, **no `roles`** | Any active assignment passes, so the Manager gets 200 (or 409 `CONSENT_NOT_EFFECTIVE`). Returns `child_id`, `class_id`, `display_name`, `age_months` |
| pilot profiles | `list_pilot_profiles` (l.560) | `roles={"teacher", "school_admin"}` at l.568-573, after `get_session` | Manager passes. Returns `child_id`, `display_name` (no age). Also needs `synthetic_pilot_enabled` and env local/test (409 otherwise) and lobby state |

How the guard decides (`routers/be1_common.py::require_assignment`, l.88-155): assignment rows are first filtered by the account role. A `school_manager` account keeps only `school_admin` rows. A `teacher` account keeps only `teacher`, `guide` and `observer` rows. Other account roles or missing rows give the uniform 404. A role refusal inside a covered organization gives **403 `ACTION_NOT_ALLOWED`**. So passing `roles=` that excludes `school_admin` gives the Manager exactly 403, and gives a Teacher account the same result as today. Assignment roles allowed by `ck_be1_assignment_role`: `school_admin`, `teacher`, `guide`, `observer`.

Who may call today: both routes, any Manager of the organization (any class, because an org-wide `school_admin` row has `class_id` NULL) and any Teacher account with a covering row. After T0.11: Teacher accounts only.

OpenAPI: `BE1_ERROR_RESPONSES` (`be1_common.py` l.49-51) already declares 403 on the router, so the schema and `tests/contract/test_openapi_contract_catalog.py` do not change.

## 3. Change

Two edits in `be1_registry.py`, no new route, no DDL:

1. `list_profiles`: add `roles=frozenset({"teacher", "guide", "observer"})` to the `require_assignment` call. This keeps today's behaviour for every Teacher-account row.
2. `list_pilot_profiles`: change `roles={"teacher", "school_admin"}` to `roles={"teacher"}`.

Decision T0.11-a (draft; the coordinator assigns the D-066 number): refusal is by allow-listing the Teacher-side roles, not by naming `school_admin`, so a future assignment role cannot slip in. The existing 404-before-403 order is kept (an out-of-scope caller still gets the uniform 404).

Finding F-1 (not fixed here, report to the coordinator): `list_pilot_profiles` calls `get_session` before the assignment check, so a caller can tell an unknown session (404 `SESSION_NOT_FOUND`) from a foreign one (404 `RESOURCE_NOT_FOUND`). It is a CONV-1 leak of existence, predates T0.11 and changing it alters test behaviour beyond the interim guard. Proposed owner: T0.9 scope guards.
