## 4. Authorization (2 reviews)

Order: occurrence lookup; caller facts; decision; class state; replay; preconditions. New pure decision `decide_child_data` in the domain module: no active row for the caller in the organization, or no row for exactly this class (an org-wide NULL-class row is not an assignment), a non-`teacher` identity, a School Manager, a Parent, a Platform Admin: uniform **404** `RESOURCE_NOT_FOUND`; an exact-class `guide` or `observer` row, or a `teacher` row that is not `responsible_teacher_ref`: **403** `ACTION_NOT_ALLOWED` (in scope, role refused; no child data in the body). The check runs on **every** command and read from the current assignment rows (FR-T-14, l.553): a revoked assignment gives 404 at the next call, and a confirmed selection of a former Teacher cannot be used (T-4b2 re-checks). The Manager never receives names or ids (O-PRIV, T-7a).

## 5. State machine and concurrency

States: `OPEN -> CONFIRMED -> CONSUMED` (T-4b2 only); `OPEN|CONFIRMED -> EXPIRED|STALE|VOID`; `EMPTY` is terminal at birth. All commands take the occurrence `FOR UPDATE`, then the class `FOR SHARE` (lock order shared with T-4b2 and T-5a: occurrence, class, selection, story run), so two selections of one occurrence serialize: the second sees the first's live row and returns it. Backstops in the database: `uq_sel_live` (one live row per occurrence), `uq_sel_draw` (one draw and one reselect per occurrence, plan and run cycle). The confirm is a compare-and-set `UPDATE ... WHERE state='OPEN' AND revision=:n AND expires_at>:now`; two confirms: one wins, the other replays by key or gets 409. A receipt-key race is handled as in T-3a (`IntegrityError`, rollback, replay).
