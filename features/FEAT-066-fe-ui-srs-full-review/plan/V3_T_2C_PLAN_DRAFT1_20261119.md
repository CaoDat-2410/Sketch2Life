## 2. Decisions (SRS-cited)

- **T2C-D1 Idea route (l.1665, FR-P-03 l.512, BR-23 l.267, l.1413).** `POST /v1/story-runs/{run_id}/idea`, key required (1-128), body `AddRunIdeaRequestV1` (`extra=forbid`): `expected_run_revision` (required, l.1665), then either (`text` 1-500 chars and/or `audio_ref` `upl_...`) or `transcript_correction {base_revision, text 1-500}`; mixing the two groups, or none, is 400 `INVALID_REQUEST`. Allowed run states `INPUT_PROCESSING`, `INPUT_REVIEW`, `SUBJECT_REVIEW` (before the subject gate), otherwise 409 `INVALID_STATE_TRANSITION`; stale revision 409 `STALE_REVISION` with `current_version`. Each text or audio submission writes input revision N+1 (copy-forward of drawing, context and its confirmation, as `attach_artwork`; typed idea and voice reference replaced); a correction writes only a new transcript revision on the same input. Receipt `SUBMIT_IDEA`, scope `STORY_RUN/{id}`, replay returns the stored 202. Audio goes through `/idea`, not `/assets` (see Q-2c-2).
- **T2C-D2 Audio admission (l.982, BR-23, l.1942, l.1664).** The `audio_ref` is resolved with `resolve_completed_upload` (T-2b helper): purpose `RUN_AUDIO`, `COMPLETED`, this run, caller scope, `CLEAN`; any miss is the uniform 404. Size at most 20,000,000 bytes (re-checked), duration at most 120 s read from the bytes by a new pure parser `infrastructure/media_validation/audio_duration.py` (WAV by stdlib `wave`, MP4/M4A by the `mvhd` atom; no decoder dependency): over either limit is 413 `AUDIO_TOO_LARGE`, an unreadable file 422 `UPLOAD_CONTENT_MISMATCH`. Upload policy: `RUN_AUDIO` enabled for `audio/wav` and `audio/mp4` (Q-2c-1); the shared signature table gains `audio/mp4` (bytes 4-8 `ftyp`); resolver `ParentRunAudioResolver` and `ensure_accepting_audio` (states above); `AUDIO_TOO_LARGE` message added. This completes T-2a-DEC-5.
- **T2C-D3 ASR step behind a port (OD-13, l.731, FR-P-03).** Port `SpeechTranscriberPort.transcribe(TranscriptionRequest) -> TranscriptionResult` (text, language, model revision, config hash, optional segment timing) in `application/ports/parent_story_inputs.py`; `FixtureSpeechTranscriber` answers only for an explicit mapping of audio SHA-256 to text (unknown input is a recoverable failure). `app.state.speech_transcriber` defaults to `None`: the transcript stays `PENDING`. When composed, the T-2b `ParentInputJobRunner` completes it after the response. No Whisper or Modal call. The ASR transcript text is untrusted data and is not safety-screened here (FR-AI-12 l.578 policy does not exist yet): recorded as debt; it only reaches the adult for review.
- **T2C-D4 Transcript confirmation, TD-04 (l.512, l.1713, l.871, l.1726, l.1829).** Explicit command `POST /v1/story-runs/{run_id}/transcript-confirmation` (route name follows the existing `subject-/context-/script-confirmation`; not an SRS route, TD-04 candidate), key required, body `{expected_transcript_revision, transcript_sha256, confirmed: true}`. 200 `ParentTranscriptConfirmationV1 {request_id, story_run_id, transcript_revision, state "CONFIRMED", run_revision, run_state}`. Hash is the SHA-256 of the effective text (adult-corrected text, else raw transcript, UTF-8). Wrong revision or hash: 409 `STALE_REVISION` (`current_version` = latest transcript revision). State other than `NEEDS_CONFIRMATION` (pending, failed, superseded): 409 `INVALID_STATE_TRANSITION`; an already confirmed same revision and hash is a 200 no-op (as `confirm_context`). Effective text plus the typed idea (joined by one space) over 500 characters: 422 `INVALID_REQUEST` with field error `transcript` `TOO_LONG` (no silent truncation; the adult shortens it by a correction). One confirmed transcript per voice asset, enforced by a partial unique index.
- **T2C-D5 Transcript read (l.780, l.1708 "rà soát transcript", BR-34).** `StoryRunDetailV1` must not carry the raw transcript (l.780, l.1164), so the adult reads it from `GET /v1/story-runs/{run_id}/transcript`: 200 `ParentRunTranscriptV1 {story_run_id, transcript_revision|null, state NONE|PENDING|NEEDS_CONFIRMATION|CONFIRMED|FAILED, origin, text, transcript_sha256, language, error_code, run_revision}`; owner only, uniform 404, `Cache-Control: private, no-store`. No log, audit or error body carries the text (l.942, NFR-03). TD-04 extension, candidate shape. The run response `ParentStoryRunResponseV1` is not changed (the Android projection test pins its keys).
- **T2C-D6 Run state machine (l.394).** `idea` with audio sets `INPUT_PROCESSING` and a `PENDING` transcript; ASR success or recoverable failure sets `INPUT_REVIEW`; transcript confirmation sets `SUBJECT_REVIEW` when an understanding exists for the current drawing, else `INPUT_PROCESSING`. `record_understanding` now sets `INPUT_REVIEW` instead of `SUBJECT_REVIEW` while the current input has a voice asset without a confirmed transcript; text-only runs behave as today. Gate: `reserve_story_revision` (old and new story routes) refuses with 422 `TRANSCRIPT_NOT_CONFIRMED` (l.871) when the current input has voice and no confirmed transcript, and builds `adult_confirmed_idea` from typed idea plus confirmed transcript text (at most 500). `confirm_subject` stays gated by `SUBJECT_REVIEW`.
- **T2C-D7 Job refs (l.1665 "202 input/ASR job refs").** Response `ParentRunIdeaAcceptedV1 {request_id, story_run_id, input_revision, run_revision, run_state, idea_source TEXT|VOICE|TEXT_AND_VOICE, transcript {transcript_revision, state}|null, job}`; `job` is `null` until Q-J (see T-2b section 6). Polling is the transcript read.
- **T2C-D8 Lifecycle (BR-23 l.267, BR-26 l.270, l.1472).** Audio, raw transcript and corrected text live until run deletion: the purge store lists `transcript_revisions` child ids, deletes them before `run_inputs`, and includes `voice_asset_ref` in `assets_referenced_by_other_runs`; a test proves the purge plan and sweep leave no audio or transcript.
