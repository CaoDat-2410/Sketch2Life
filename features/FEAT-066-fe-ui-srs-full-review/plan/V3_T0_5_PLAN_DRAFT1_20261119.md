## 2. SRS and decision (TD-18, draft D-066-95)

- SRS has no demo route; `/v1/story-runs` is the real Parent surface (l.1649-1699 route family, l.1675). A local demo may not silently stand in for it.
- **Do not move the lite prefix**: TD-18 allows it only "if clients can be re-pointed"; the pinned contract, the Bruno collection and the documents cannot be re-pointed in this task. Recorded as not done.
- **Fail loudly, then log (answer to TD-18):**
  1. At startup, compute the collision from the real route tables, not from a hard-coded prefix: the set of (method, path) of the real Parent router (and any other real router mounted later, for example the T-2a upload sessions that already share `/v1/upload-sessions` with the demo) that the lite router shadows.
  2. If the flag is `1` and the collision set is non-empty, startup raises `ValueError` naming the first shadowed routes (counts and 3 examples, no secrets) **unless** the process also sets the explicit acknowledgement `STORYRUN_LITE_MAIN_DEMO_REPLACES_PARENT_ROUTER` to `1` (same `0`/`1` validation as the main flag). The acknowledgement is only meaningful with the main flag, is read in the same place, and is validated before any router is mounted.
  3. When acknowledged, log one WARNING on logger `sketch2life.api`: `storyrun_lite_main_demo_replaces_real_routes shadowed=<n> parent_router_mounted=false env=<env>`, set `application.state.story_demo_replaces_real_routes` to the shadowed list (read-only) and add one sentence to the OpenAPI description naming the replacement. A flag `0` run logs nothing new and behaves as today.
- Why raise rather than only warn: the owner asked for a loud failure, a silent log is what the audit (AUD-S §5) found; the acknowledgement keeps the demo available with one added variable in the demo launch instructions.
