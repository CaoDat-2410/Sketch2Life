## 2. SRS and decision (TD-20, draft D-066-94)

- l.1675 `GET /v1/jobs/{job_id}`: actor of the run, "Job phải thuộc scope của actor", 200 job status with version. l.806 poll status with version and safe error. l.779 AiJobStatusV1: exactly one target kind/ref of `STORY_RUN`, `VIDEO_GENERATION`, `VIDEO_GENERATION_SCENE`, `LESSON_SOURCE_DOCUMENT`, `LESSON_LIBRARY_VERSION`, `LESSON_VERSION_VISUAL_ASSET`, `LESSON_SKETCH_DECK_REVISION`, `PARENT_SKETCH_GUIDE`. l.786 poll 2 s to 10 s, ETag/job version. l.865: 404 `RESOURCE_NOT_FOUND`, one shape for missing and out-of-scope. l.1711: no drill-down into profile/story/media.
- **Registry (answer to TD-20):** one frozen registry in the application layer, `application/job_kinds.py`: `JobKindSpec(target_kind, job_types, scope_rule, eligibility)` for exactly the eight kinds above. `job_types` maps an internal `job_type` string to a kind; it is empty for every kind at HEAD, and each producer task (T-3b, T-2c, WP-1, T-2d) adds its job type in the same commit. `scope_rule` defaults to deny; `eligibility` defaults to "ineligible", which withholds `result_refs` (fail closed). A job whose type is unregistered answers 404, so BE2 pilot jobs never leak through this route.
- **Principal resolver (answer to TD-20):** the route takes `Depends(get_verified_adult)` and `Depends(get_db)` (not the fixture `Authorization: Fixture` scheme) and resolves a `JobActor(account_id, role, memberships)` from `be1_adult_identities` (active, issuer matches, role present) plus active `be1_organization_assignments`. No resolvable actor, or role `platform_admin` (no tenant drill-down, l.1711), answers the uniform 404. Mapping: `teacher` to `PrincipalRole.TEACHER`, `school_manager` to `ADMIN`; there is no `DEVICE` on this route (Child devices use their own grant routes). `parent`: the resolver calls a `ParentJobScopePort` whose HEAD implementation always answers "not owned" (no Parent job can exist before T-2c/WP-1 add owner-scope DDL); a fake port proves the seam in tests.
- The reader picks the organization from the stored job, requires an active membership in it, builds an org-bound `Principal`, then asks `AuthorizationPort.decide(READ_JOB, job.scope)`. HEAD production authorisation is "deny" for every kind; the generic rule implemented and tested for fixtures is: school_admin org-wide, teacher only for the class of `scope.session_id`. Per-kind rules (run owner, lesson owner) arrive with the producers.

## 3. Route and shapes

- `GET /v1/jobs/{job_id}`, tag `Jobs`, runtime OpenAPI only (like other uncatalogued routes); FE-projected spec inclusion (`SRS_V22_INCLUDED_OPERATIONS`) deferred to T-3b so the FE contract does not change before a job exists (open question 2).
- `job_id` pattern as `ai_jobs.py:30`; malformed id: 400 `INVALID_REQUEST` with `field_errors`. No `Authorization`: 401 `AUTH_REQUIRED`. Out of scope, missing, unregistered kind, unreadable: identical 404 `RESOURCE_NOT_FOUND`.
- 200 body: the `AsyncJobEnvelopeV1` projection of `project_job` for TEACHER/ADMIN plus `target_kind` and `target_ref` (from registry and `scope.target_id`), `meta.poll_after_ms`, `meta.resource_revision`; headers `ETag`, `Cache-Control: private, no-cache`, `Vary: Authorization`. `If-None-Match` (strong or `W/`, list form) gives 304 with the ETag only while the actor is still authorised. Read-only: no POST/PUT/DELETE, no completion route.
- Errors use the six-field §9.8 envelope: add `/v1/jobs` to `CONV1_PREFIXES` (`error_envelope.py:16-22`) so `HTTPException` from dependencies is normalised; check `test_http_error_envelope.py` prefix assertions.
