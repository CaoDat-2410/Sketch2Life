# V3 T-1c plan, Draft 2: `playback-token`, stream route, `StoryRunDetailV1` aggregate

Date 2026-11-19. Goal v3b, T-1c (WP-1, P-05, AUD-P#10 and #24; TD-07, TD-22). Draft 2 replaces Draft 1 after plan review R1 (0 P1 / 4 P2 / 8 P3); every P2 and the cheap P3s are applied. Self-contained. Facts read at HEAD `a076752d`; builds on T-1a Draft 2 (tables, generation rows, job projection, handle) and T-1b. No DDL, no capacity, quota, billing or payment code.

## 1. Verified facts

- F1 `GET /v1/story-runs/{id}` returns `ParentStoryRunEnvelopeV1{request_id, story_run}` or, from `DELETE_PENDING` on, the content-free lifecycle envelope (D-208), which returns before any other read. `ParentStoryRunResponseV1` has no `extra="forbid"`. It is built in **two** places: `_response(record)` in `routers/parent_story_runs.py` and `_story_response` in `routers/parent_ai.py` (legacy `/api/parent/v1/ai/...`), both from `ParentStoryRunRecord` (`application/ports/parent_story_runs.py`, filled by `SqlParentStoryRunRepository.get_run`). The family sets no `ETag` today.
- F2 `ObjectStoragePort.get_object(key)` returns a `StoredObject` with a readable `body`, or `None` when absent; failures raise `ObjectStorageFailure`; there is no range read.
- F3 No playback grant table exists and DDL-B1 names none. `application/video_playback.py` (BE2 pilot) is organization-scoped and unrelated.
- F4 `get_db` (`interfaces/http/be1_runtime.py`) is a yield dependency; probe on FastAPI 0.141.1: its exit runs after the last response chunk, so a streaming route holds the session for the whole download.
- F5 T-1a leaves the generation row with the physical `output_asset_ref` (never serialized), three validation states, `job_ref`, scenes, and one job mapper shared with `GET /v1/jobs`.
- F6 Existing tests build or compare the record: `contract/test_parent_story_lifecycle_contract.py:74` and `unit/test_seed_s7a.py:48` construct `ParentStoryRunRecord`; `integration/test_seed_s1_postgres.py:106-109` and `integration/test_seed_s7a_postgres.py:120-123` rebuild `ParentStoryRunResponseV1` from every dataclass field (`fields(record)`).

## 2. Decisions (SRS-cited)

| ID | Decision | Basis |
|---|---|---|
| D1 | `POST /v1/story-runs/{id}/playback-token`, no body, no idempotency key (a grant, no state change, **no database write**; it does not reset the idle timer). Preconditions: `_require_parent` and the owner-scoped lookup; run `VIDEO_READY`; current generation `READY` with technical, consistency and safety states `PASSED` and an output asset. Else 404 (not owner) or 409 `INVALID_STATE_TRANSITION`. 200 `{request_id, playback{token, expires_at, stream_path, media_type "video/mp4", asset_ref}}`, `Cache-Control: no-store`. | l.1676, l.575, l.1691 |
| D2 | Token (TD-07 deviation, Q1): opaque signed token `ptk1.<header>.<payload>.<mac>` (HMAC-SHA256, strict base64url, at most 512 bytes, key id in the header for rotation, `hmac.compare_digest`), payload = run id, generation id, actor scope digest, expiry (no nonce). TD-07 recommended "stored hashed", which needs a table outside DDL-B1; the stateless form is used and **every stream request re-checks** current ownership, run state, generation identity and visibility (same revocation effect, l.576, l.1691). Lifetime 300 s (settings, maximum 900 s). The secret is a `SecretStr` setting of at least 32 visible ASCII characters (as `ops_probe_token`), never echoed. **Fail closed at the route, not at startup:** with no secret the token and stream routes answer 503 `PROVIDER_UNAVAILABLE` and a startup warning names the setting without its value; production still starts (consistent with T-1a's 503 when adapters are unconfigured, and no existing settings test changes). `local` and `test` may use an ephemeral per-process key (a token minted by another worker then fails with 401 `INVALID_TOKEN`; local runs use one worker). The token is never logged, stored or put in an error body. | l.1691, l.1693, TD-07 |
| D3 | Stream route `GET /v1/story-runs/{id}/playback`: the Firebase bearer is **required** (`get_verified_adult`) and the token travels in header `X-Playback-Token` (never in the URL, l.1693). The verified principal's scope ref (the Story owner digest) must equal the token's actor digest, else the uniform 404, so a leaked token is useless to anyone else (l.1691 "actor/run"). Order: token shape and MAC (401 `INVALID_TOKEN`), expiry (401 `TOKEN_EXPIRED`), principal active with role `parent` and matching issuer, path run id equals token run (else uniform 404), owner-scoped lookup (404), run `VIDEO_READY`, current generation equals the token's and is `READY` (404), object read (`None` gives 404, `ObjectStorageFailure` gives 503 `STORAGE_UNAVAILABLE`). A wrong owner or a revoked grant answers the uniform 404; `AUTHORIZATION_REVOKED` (l.875, a job and run outcome) is not produced for a Parent. `HEAD` is not defined (405). | l.1691-1693, l.863-865, l.875 |
| D4 | Streaming: authorization runs in a short scope with its own session (`session_factory()` or rollback and close) that is **closed before `StreamingResponse` is built**, so no connection is held during the download. The generator reads 64 KiB chunks from `ObjectStoragePort.get_object` (skipping to the range start; no port range read, debt for the real adapter), closes the `StoredObject.body` in a `finally`, stops on client disconnect, and refuses an object over the ceiling (settings, default 100 MiB, 503) before the first byte. Headers: `Accept-Ranges: bytes`, `Content-Type: video/mp4` (fixed, from the validated record), `Content-Disposition: inline` without a file name, `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`. One `Range` gives 206 with `Content-Range`; malformed or multiple ranges 416 with `Content-Range: bytes */<size>`. No bucket, key, URL, list or download route (l.1692). The physical key comes from the Story-owned generation row (T-1a section 4, `output_asset_ref`), not from Core tables. | l.1692, l.575 |
| D5 | `StoryRunDetailV1` is realised by extending `ParentStoryRunResponseV1` in place with optional fields only (l.1635 allows additive fields). **One builder:** `_response` moves to a shared function used by `routers/parent_story_runs.py` and `routers/parent_ai.py`, so every route that returns the model shows the same shape. New fields: `video` (null until a generation exists): `current_generation_id`, `generation_no`, `kind`, `state`, `job{job_id, state, stage, retryable, error_code}`, `scenes[{scene_index, state}]`, `playback{state AVAILABLE or HIDDEN or UNAVAILABLE, asset_ref, token_route}`, `video_requests_used`, `video_requests_remaining` (the run cap of T-1a D5, named so a client does not take them for quota), `admission_pending`, `history[{generation_id, generation_no, kind, state}]` (accepted rows, at most three); `quota{state "UNAVAILABLE", granted, used, available, month: null}` (TD-22: never zero; field names follow Billing Draft 9 §7.2 `read_balance`; a constant, no port, no reader, no setting); `timeline[{event, at}]` derived from existing timestamps. The playback "ref" is the readiness descriptor and route name; a token exists only after the explicit POST. The record gains defaulted fields whose names equal the model field names (F6). | l.780, l.805, l.1811, AC-41, TD-22 |
| D6 | Composition (AC-41, l.1811): one Story-owned read in `infrastructure/story_video/repository.py` called by `get_run`, bounded to one generation row, its scenes and at most three history rows; the job part uses the single mapper shared with `GET /v1/jobs` (T-1a D10); no read of `ai_jobs`, Billing, Lesson or Core tables. This follows T-1a Q2: a different answer there changes the job part. Never exposed: prompts (`visual_prompt`), raw transcript, hidden story revisions, provider text, rejected-video content, foreign scope, the physical key. The `asset_ref` handle is `vid_` plus the generation id. | l.780, l.1164, l.875 |
| D7 | ETag: strong `"d1-<first 32 hex of sha256 of the canonical (sorted-key) body without request_id>"`, `Cache-Control: private, no-cache`, `Vary: Authorization`; the input includes every field that can change the body (`playback.state`, counts, scene states, `timeline`) and no per-call value; `If-None-Match` is evaluated **after** authorization against a body recomputed from the database (no cache); a match gives 304. Content hash rather than the run revision because generation and scene states change without a run revision bump. Detail (non-lifecycle) response only; commands keep body `expected_revision`. | l.1811 |
| D8 | Public safe failure codes in `video.job.error_code`: `VIDEO_SAFETY_BLOCKED`, `VIDEO_DEADLINE_EXCEEDED`, `VIDEO_TECHNICAL_FAILURE`, `PROVIDER_UNAVAILABLE`; any other stored `safe_failure_code` maps to `VIDEO_TECHNICAL_FAILURE`. T-1a's job mapper uses the same set. | l.875 |

## 3. Routes and contract

| Method, path | Actor | Success | Errors |
|---|---|---|---|
| `POST /v1/story-runs/{id}/playback-token` | Parent owner | 200 token | 404; 409 `INVALID_STATE_TRANSITION`; 503 `PROVIDER_UNAVAILABLE` (no secret) |
| `GET /v1/story-runs/{id}/playback` | Parent owner presenting the token | 200 or 206 bytes | 401 `INVALID_TOKEN`, `TOKEN_EXPIRED`; 404; 405 (HEAD); 416; 503 `STORAGE_UNAVAILABLE`, `PROVIDER_UNAVAILABLE` |
| `GET /v1/story-runs/{id}` | Parent owner | 200 extended envelope with `ETag`, or 304 | 404 |

Authorization (2 reviews): issuing re-reads current ownership; streaming re-reads it on every request and also requires the live bearer to match the token's actor, so cancel, delete, completion, hide-by-unsuitable, closeout, a foreign account and a stolen token all end at the uniform 404 or 401 at the next request. The wrong-role answer is whatever T0.9 leaves. Teacher assignment recheck is a seam only (T-4a1). The three routes are runtime-only in the OpenAPI projection (as T0.4); the existing `GET /v1/story-runs/{run_id}` entry of `openapi_srs_v22.py` carries the additive fields.

## 4. DDL

None. The stateless token avoids a grant table. If Q1 answers "stored", a `story.playback_grants` table needs its own DDL approval and this task moves later.

## 5. Tests

Unit: token round trip, tamper, bad shape, oversize, expiry (injected clock), key id rotation, wrong run, wrong actor; the token string is absent from logs and error bodies; range parser (valid, open ended, suffix, malformed, multiple, 416 header); composer privacy and counts (no prompt, transcript or provider text; `quota` marker; counts after one, two and three requests; code mapping of D8); ETag stability (`request_id` excluded) and change on each state; no secret gives 503 on both routes while the app starts. Contract: the three routes and the route table of `test_app_composition.py`; additive schema (old fields unchanged); 304 after authorization only; header set; no storage key, bucket or URL in any body or header; both builders return the same shape. PostgreSQL (fresh database): Parent run to `READY` through the T-1a fixture runner, then token, `200`, `206`, `416`; **another authenticated Parent with a valid token gets 404**; a token without the bearer gets 401; after `video-unsuitable` a new token is 409 and the old token 404; after cancel the stream is 404; tampered 401; expired 401; after `complete` a token is 409; detail ETag changes when the generation moves and `If-None-Match` returns 304; no session or connection is open while chunks are produced; the object `None` case gives 404.

## 7. Review rule, FE impact, rollback

**2 reviews**: a new playback authorization guard and a change to a response Android and web already use. FE impact: Android adds the token call, the header-borne stream and the extra fields (strict decoders need a check against `.worktrees/mobile` and `.worktrees/ui`, including the frozen M2 projection test `parentStoryRunProjectionContract`); the web `<video>` case is Q2. Rollback: remove the routes (the additive response fields may stay).

## 8. Risks

R1 Stateless tokens cannot be revoked before expiry; mitigated by the per-request recheck, the bearer binding and 300 s. R2 Header transport does not suit a plain web `<video src>` and the backend has no CORS (Q2). R3 Whole-object skip-read through the port (latency; ceiling plus debt). R4 Additive fields can break a strict decoder. R5 A deployment with no signing secret serves 503 on playback only; recorded for the deployment owner.

## 9. BLOCKED_OPEN and ownership

- **Q1:** is the stateless signed token acceptable instead of TD-07's "stored hashed" token (new table outside DDL-B1)? Default yes.
- **Q2 (client, OPEN-WITH-DEFAULT):** header transport cannot serve a plain web `<video>` element and a browser fetch would need CORS (the backend has none, T0.6). If the web player needs a URL-borne token, ask for a one-time exchange route; not built. The owner may instead choose a pure capability token (no bearer on the stream) and accept the leak risk of F-01.
- **Q3:** the SRS asks for a "timeline" (AC-41, l.805) but no state-history store exists and "no read-model table" is a rule. Default: derived from existing timestamps; a true history needs an owner decision.
- **Q4:** token lifetime (300 s default; the SRS says only "short-lived").
- **Q5 (OPEN, not decided here):** after `complete` or idle closeout the video is no longer playable (l.1676 needs `VIDEO_READY`, "run active until complete, closeout or cancel"), while BR-38 l.282 and FR-B-11 l.597 say that stored data stays viewable after quota runs out. T-1b D5 records the same note; the owner decides whether a `COMPLETED` run may issue tokens.
- Quota summary content: OWNED_BY_OWNER (the quota reader); only the marker is delivered here.
