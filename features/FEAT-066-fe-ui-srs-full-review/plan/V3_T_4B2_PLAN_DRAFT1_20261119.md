- F2 `story.runs` (tables in `infrastructure/story_run_lite/tables.py`; DDL `20261102_story_run_lite`, `20261112_parent_story_context`, `20261119_frc08_lifecycle_scope`): `actor_scope_kind IN ('PARENT_ACCOUNT','ORGANIZATION')`, `profile_ref` (nullable since frc08), `child_age_months` CHECK 36-120, unique partial index `uq_story_run_active_parent`. **No Teacher owner column, no occurrence, plan or activity pin** exists. `run_inputs` has `lesson_pin_snapshot` (JSONB, hashed, at most 1 MiB), `context_snapshot` (at most 32 KiB, CHECK `ck_story_run_input_parent_context`: with the snapshot, `source_profile_revision_ref varchar(36)` and `context_revision` are required).
- F3 Lock release at HEAD is hand-written at several sites that set `active_owner_parent_account_id` to NULL (`parent_story_repository.py` cancel and failure paths; `story_run_lite/repository.py` failure and delete paths) and will gain more (T-1a, T-1d1 closeout, T-13a). None knows a Teacher column.
- F4 Alembic: the Story chain is branch `frc08_lifecycle`, head `20261119_frc08_lifecycle_scope`; planned children: `20261120_b1_0001` (T-2c), `20261120_vb_0002` (T-1a). The occurrence is `lesson.occurrences` (F1 of T-4b1); T-4b1 adds `lesson.occurrence_child_selections` (state `CONFIRMED`, `consumed_run_ref`).
- F5 Error codes `TEACHER_ACTIVE_RUN_CONFLICT`, `SAMPLE_VIDEO_ALREADY_EXISTS`, `LESSON_PLAN_NOT_APPROVED`, `MULTI_CHILD_NOT_SUPPORTED` are in the SRS list (l.866, l.871) but absent from the code; `app.py` keeps a small table of Vietnamese safe messages.

## 2. Decisions (SRS-cited)

| ID | Decision | Basis |
|---|---|---|
| D1 | **One route, two bodies.** `POST /v1/story-runs` dispatches on the caller's account role: `parent` keeps the Parent body and behaviour **byte for byte** (a contract test pins schema, status and error bodies); `teacher` takes the Teacher body of D2. A role/body mismatch (Parent with Teacher fields, Teacher with a Parent body) is the uniform 404, so neither role learns the other flow. Catalog row documents both request schemas (`oneOf`). | l.1663, l.864 |
| D2 | **Teacher body** (`extra=forbid`): `profile_ref{kind:"MANAGED_PROFILE", id}`, `occurrence_id`, `plan{revision_no, plan_hash}`, `activity_id` (a `plan_activity_id` of that plan), `selection_id`, `selection_sha256`; header `Idempotency-Key`. An array, a second profile, `child_ids`-style keys, or a `profile_ref.id` different from the confirmed child: **422 `MULTI_CHILD_NOT_SUPPORTED`** (pre-check of the raw JSON before model validation). No lesson-version field: the pin comes from the plan. | l.1445, l.1723, FR-T-10 |
| D3 | **Pins and snapshots.** New `story.runs` columns (DDL-B2, section 5): `occurrence_ref`, `created_by_actor_ref`, `active_owner_teacher_id`. | D4 | **Owner and scope.** `actor_scope_kind='ORGANIZATION'`, `actor_scope_ref=organization_id` (consistent with the frc08 owner-scope CHECK of the lifecycle tables); lock `active_owner_teacher_id` = the Teacher's `account_id` (varchar 36); `created_by_actor_ref` = same value, provenance only (l.553). `profile_ref` = child id, `child_age_months` from the profile. | D7 | **Lock release by trigger** (DDL-B2): a `BEFORE UPDATE OF run_state` trigger clears `active_owner_teacher_id` when the new state is `COMPLETED`, `FAILED`, `ABANDONED`, `DELETE_PENDING` or `DELETED`, plus a CHECK that a terminal row holds no Teacher lock. ## 5. DDL-B2: exact migration (Teacher owner, pins, lock)

File `backend/alembic/versions/20261120_b2_0001_teacher_run_owner.py`, `revision = "20261120_b2_0001"` (16 chars), **`down_revision` = the single head of the `frc08_lifecycle` branch at implementation** (read `python -m alembic heads`; expected `20261120_vb_0002` after T-1a, else `20261120_b1_0001` after T-2c, else `20261119_frc08_lifecycle_scope`). It must chain after the pending T-2c and T-1a migrations; a second child of one revision makes two heads and is refused. No label, no `depends_on`. Chain order is serial: T-2c, T-1a, then this (never in parallel with another story-chain migration).
`upgrade()` on `story.runs`: add `active_owner_teacher_id varchar(36) NULL`, `occurrence_ref varchar(36) NULL`, `created_by_actor_ref varchar(36) NULL`; CHECK `ck_story_run_teacher_pins`: `(occurrence_ref IS NULL) = (created_by_actor_ref IS NULL)`; CHECK `ck_story_run_teacher_owner`: `active_owner_teacher_id IS NULL OR (occurrence_ref IS NOT NULL AND actor_scope_kind='ORGANIZATION' AND active_owner_parent_account_id IS NULL)`; CHECK `ck_story_run_teacher_lock_state`: `active_owner_teacher_id IS NULL OR run_state NOT IN ('COMPLETED','FAILED','ABANDONED','DELETE_PENDING','DELETED')`; unique partial indexes `uq_story_run_active_teacher (active_owner_teacher_id) WHERE active_owner_teacher_id IS NOT NULL` and `uq_story_run_active_occurrence (occurrence_ref) WHERE active_owner_teacher_id IS NOT NULL`; index `ix_story_run_occurrence (occurrence_ref) WHERE occurrence_ref IS NOT NULL`; function `story.release_teacher_lock()` and trigger `trg_story_run_release_teacher_lock BEFORE UPDATE OF run_state ON story.runs FOR EACH ROW` (D7). No FK to `lesson.occurrences` (opaque ref, no cross-owner foreign key). Existing rows need no backfill (all new columns NULL).
`downgrade()`: refuses while any row has a non-NULL new column; else drops trigger, function, indexes, CHECKs, columns. **Rollback by explicit revision:** `python -m alembic downgrade <the parent revision id>`, never `-1`; verify on a second disposable database that `upgrade heads`, that downgrade and a second `upgrade heads` succeed.
ORM mirror in `story_run_lite/tables.py`; static test of columns, CHECK, index and trigger names.

## 6. Concurrency

Two creates, same Teacher, different keys, same or different occurrence: one wins by `uq_story_run_active_teacher` (409 `ACTIVE_RUN_EXISTS` for the loser; no orphan input row, the transaction rolls back). Same key twice: advisory lock on the key (as `_lock_idempotency`), one run, replay. Two creates racing for one selection: the `FOR UPDATE` plus compare-and-set let one consume it; the other is 409 `INVALID_STATE_TRANSITION`. A plan confirm racing a create: the occurrence lock orders them (a create after the confirm sees the new plan and refuses the old pin with 409 `STALE_REVISION`). A suspend racing a create: the class lock orders them.

## 9. FE, rollback, risks

FE: web Teacher run screens send the Teacher body after confirming a selection; Android sends the Parent body only (unchanged, test-pinned). Rollback: revert the commit and `downgrade` to the parent revision (refused while Teacher rows exist). Risks: R1 route dispatch could alter the Parent path (pinned by the contract test and the Parent PostgreSQL suites); R2 one Lesson-row compare-and-set inside the Story transaction (D11); R3 the release trigger is silent (reviewed as the single place; a PostgreSQL test per terminal state); R4 `occurrence_ref` is an opaque ref with no FK (a deleted occurrence is impossible, DDL-A forbids delete); R5 T-1a may add terminal run states that the trigger list lacks: the implementer re-reads `ck_story_run_state` at that time and aligns the list.
