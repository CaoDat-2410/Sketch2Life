# V3 T-1d1 plan, Draft 1: adult-wait closeout transitions (FR-C-11), not an HTTP route

Date 2026-11-19. Goal v3b, T-1d1 (WP-1 T-1d scope). Facts read at HEAD `0ee27069`; builds on T-1a (columns, progress service) and T-1b. The 144-hour reminder is T-1d2 (v4, needs WP-8) and is not built. No DDL here, no capacity, quota, billing or payment code.

## 1. Verified facts

- F1 HEAD has no sweeper, no `adult_wait_started_at`, `last_meaningful_activity_at` or `finished_at`; T-1a adds the three columns (nullable) and backfills wait-state runs from `updated_at`. `ck_story_run_state` gets `ABANDONED` from T-1a.
- F2 HEAD runs start in `INPUT_PROCESSING` with no job (the adult must still attach a drawing), then `SUBJECT_REVIEW`, `PREPARATION_REVIEW`, `SCRIPT_GENERATING`/`SCRIPT_GENERATION_UNKNOWN` (job), `SCRIPT_REVIEW`; a failed drawing job goes `FAILED` and frees the lock. There is no `DRAFT` or `INPUT_REVIEW` state at HEAD (T-2b..T-2d may add them: re-read `PUBLIC_RUN_STATES` and the check at start).
- F3 The lock is `active_owner_parent_account_id`. `ABANDONED`, `COMPLETED` and `FAILED` are delete-eligible (`DELETE_ELIGIBLE_STATES`), and `ABANDONED` is already a public state in `PUBLIC_RUN_STATES`.
- F4 Existing Parent runs already sit in adult-wait states, so the sweeper matters before WP-1 is finished (plan Draft 5 T-1d scope). Teacher runs and `active_owner_teacher_id` do not exist (DDL-B2, v5).
- F5 `story.runs` updates that set `run_state` are spread over `parent_story_repository.py` (create, artwork attach, understanding, subject and context confirmation, story reserve, complete, fail, confirm, drawing failure, lifecycle commands), so the wait clock needs one rule applied at each site.

## 2. Decisions (SRS-cited)

| ID | Decision | Basis |
|---|---|---|
| D1 | **Adult-wait predicate** (pure, `domain/story_run_closeout.py`, tested over all states): a run is in adult-wait when it has no active AI job and needs the adult: `SUBJECT_REVIEW`, `PREPARATION_REVIEW`, `SCRIPT_REVIEW`, `SAFETY_BLOCKED`, `VIDEO_READY`, `INPUT_REVIEW`, `DRAFT`, and `INPUT_PROCESSING` with `job_state` NULL (HEAD's draft: nothing uploaded yet). Not adult-wait: `INPUT_PROCESSING` with a running or reconciling job, `SCRIPT_GENERATING`, `SCRIPT_GENERATION_UNKNOWN`, `STORY_GENERATING`, `VIDEO_ADMISSION_PENDING`, `VIDEO_QUEUED`, `VIDEO_GENERATING`, `VIDEO_SAFETY_VALIDATING`, and the closed states. `VIDEO_ADMISSION_PENDING` never arms a timer. | l.503, l.394, FR-C-11 |
| D2 | **Idle closeout at +168 hours** from `adult_wait_started_at`: `VIDEO_READY` becomes `COMPLETED`; every other adult-wait state, `DRAFT` included, becomes `ABANDONED`. Effects in one transaction per run: `active_owner_parent_account_id` NULL, `finished_at` = now, `adult_wait_started_at` cleared, `revision` and `version` +1. Content, generations and assets are kept until the user deletes the run; no outbox event, no purge. Playback stops with `VIDEO_READY` (T-1c recheck). | l.503, l.517 (FR-P-08), l.383, l.394 |
| D3 | **Wait clock** (the one rule of F5): `adult_wait_started_at` is set to now when a transition enters an adult-wait state (job end or failure that needs the adult, or an adult command that lands in another wait state, e.g. `SUBJECT_REVIEW` to `PREPARATION_REVIEW`), and is NULL in any state with a job or in system work. Polling, reads, push receipts and token issuance never touch it. `last_meaningful_activity_at` = now on every adult command that takes effect. A refused admission (T-1a D2) returns to `SCRIPT_REVIEW` and starts a new wait, so the next closeout is 168 hours after the refusal. A helper `wait_columns(run_state, job_state, now, adult_command)` returns the column values; T-1d1 applies it at every `parent_story_repository.py` site that sets `run_state` (T-1a and T-1b set the same columns inline at their own sites). | l.394, l.503 |
| D4 | **Generation deadline**: a generation in `ACCEPTED`, `QUEUED`, `GENERATING`, `TECHNICAL_VALIDATING` or `SAFETY_VALIDATING` with `accepted_at` + 6 hours elapsed is failed through the T-1a progress service (`safe_failure_code` `VIDEO_DEADLINE_EXCEEDED`): run `FAILED`, lock released, compute reservation settled as consumed, quota unit not refunded. The deadline runs from `accepted_at` (queue plus every stage), not from `admission_started_at`; `VIDEO_ADMISSION_PENDING` is outside it. | l.503, l.395, l.573 |
| D5 | **Entry point**: `StoryRunCloseoutService.run_once(now, batch_size)` returns counts (`completed`, `abandoned`, `deadline_failed`, `skipped`); rows are claimed with `FOR UPDATE SKIP LOCKED` ordered by clock, the state and clock are re-checked under the lock, and the update is a CAS on `revision`, so a concurrent cancel, command or second worker loses cleanly and the call is idempotent. `now` is injected. No scheduler, no CLI, no HTTP route (the periodic runner slice, D-066-73 PD-9a, calls it). Only Parent rows (`actor_scope_kind` PARENT_ACCOUNT) are touched; the Teacher owner column is a seam for DDL-B2. Logs carry counts and opaque run ids only. | l.503, NFR logging l.2075 |
| D6 | No audit row and no notification: FR-C-11 requires neither for the closeout, and a delivery failure may never block it (l.503); the reminder and its channels are T-1d2. | l.503 |

## 3. Contract

No route, no response change. The only public effect is the run state a client reads (`COMPLETED`, `ABANDONED`) and `can_delete` from the existing summary capabilities. The OpenAPI catalog is untouched.

## 4. Authorization and keys

No actor: the sweeper is a system job with no principal and no request keys. It never reads or writes content columns, never calls Billing or AI Policy except the deadline `settle` through the T-1a port, and filters strictly by the Parent scope kind.

## 5. State machine

`SUBJECT_REVIEW | PREPARATION_REVIEW | SCRIPT_REVIEW | SAFETY_BLOCKED | INPUT_REVIEW | DRAFT | INPUT_PROCESSING(no job)` to `ABANDONED`; `VIDEO_READY` to `COMPLETED`; in-flight generation states to `FAILED`. Terminal states are never touched. These pairs are one constant shared with the tests.

## 6. Tests

Unit: predicate over every public state and job state; `wait_columns` matrix; service with a fake store (counts, idempotency, injected clock, error on one row does not stop the batch). PostgreSQL (fresh database, `alembic upgrade heads`): rows seeded at 167 h 59 min and 168 h for each wait state close or stay; `VIDEO_READY` to `COMPLETED`, others to `ABANDONED`; the lock is free afterwards (a new run can be created) and story rows, generations and assets are intact; a second run changes nothing; two concurrent workers close each row once (`SKIP LOCKED`); a cancel racing the sweep leaves `DELETE_PENDING`; jobs `RUNNING` and `AWAITING_RECONCILIATION` and every `VIDEO_*` in-flight state are never closed; a refused admission restarts the wait; the deadline sweep fails an overdue generation, frees the lock, calls `settle` once and leaves a generation at 6 hours minus one second alone; the wait clock is walked through a whole M2 run (create, attach, understanding, subject, context, story, script confirmation) asserting NULL during jobs and a fresh value at each wait state; delete of an `ABANDONED` run still works; no Teacher-kind row is changed.

## 8. Review rule

**1 combined review** (plan and code together): no migration (the columns come from T-1a), no guard or contract change. It still edits the M2 repository at several sites and mutates existing rows in bulk, so the reviewer is asked to check the F5 sites one by one. If T-1a Q1 is refused and the fallback needs a migration change, the rule becomes 2 reviews.

## 9. Risks

R1 First sweep on existing data can close many old synthetic runs at once (backfill from `updated_at`); acceptable under synthetic-only (OD-06) and recorded. R2 Missing one `run_state` site would leave a stale clock; the walked-run test and a source scan (every `run_state=` in the repository goes through the helper) guard it. R3 Without T-1a Q1, `updated_at` is the only clock, and any write would reset the wait. R4 `INPUT_PROCESSING` with no job as "draft" is an inference from HEAD; T-2b..T-2d may replace it with a real `DRAFT`.

## 10. BLOCKED_OPEN and ownership

- **Q1 (OPEN-WITH-DEFAULT):** the clock start for runs that already exist at migration: default `updated_at` (faithful to l.394). The alternative (start at deployment time) avoids a mass closeout; the owner may choose before the migration runs.
- **Q2:** does `SAFETY_BLOCKED` close to `ABANDONED` when the adult never acts (default yes, l.383 "adult-wait other states")? Its exits for the adult are T-1b Q2.
- **Q3:** after a deadline failure the run is `FAILED` and the quota unit stays consumed (no refund, l.573); confirm that `FAILED`, not a return to `SCRIPT_REVIEW`, is intended.
- **Scheduling:** who runs `run_once` and how often is OWNED_BY the periodic runner slice (D-066-73 PD-9a); not built here. Reminder at 144 hours, inbox, push, e-mail: T-1d2 (v4).
