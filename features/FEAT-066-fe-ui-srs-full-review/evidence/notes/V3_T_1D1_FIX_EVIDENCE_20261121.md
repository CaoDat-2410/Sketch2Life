## 2. Decisions (T-1d1-fix-DEC-n)

- **DEC-1 (runner; FR-O-03 l.608, l.1799, l.1801, l.1988, l.2867 S12).** `run_sweepers_once(now, steps=, batch_size=, clock=)` runs reaper, reconciler, closeout in that order (what the first two hand back to the adult gets a fresh wait before the idle pass reads it), one `now` per pass, batch 1..200, naive `now` refused, a failing step counted by exception class and never stopping the others, one counts-only INFO line (`story_sweep_pass`, the heartbeat). `run_pass_locked` takes `pg_try_advisory_lock(hashtextextended('sketch2life.story-sweep.v1', 0))` on a dedicated AUTOCOMMIT connection; busy means `lock_busy`, no work; the unlock runs in `finally` and an unlock that fails or answers false invalidates the connection (PostgreSQL drops the session lock). The lock is a duplicate-work guard only: every row stays compare-and-set. `run_loop` has an injected `wait` (a failing pass waits the normal interval, never spins; `--heartbeat-file` is touched after each pass that did not raise and had no failing step: a busy lock is healthy, a step that fails every pass is not; stage 2, P3-1); `main`: `--once`, `--interval-seconds`, `--batch-size`, `--heartbeat-file`, SIGTERM and SIGINT stop, INFO logging to stdout, exit 0 at once when `SKETCH2LIFE_STORY_SWEEP_ENABLED=false` (no connection), `--once` exit 0 when the pass completed or the lock was busy and 1 when a step raised. Settings (all `SKETCH2LIFE_STORY_SWEEP_*`): enabled true, interval 300 s (1..3600), batch 50 (1..200), task lease 21,600 s (60..21,600; 6 h is the only licensed lease, l.615); local/test shorten or disable by environment. `run_scheduled_pass()` is the no-argument entry a later `rq.cron` registration would call. The reconciler step runs even with no adapters (it then fails the in-flight generations of cancelled runs, database only; pending intents and compute reservations wait for the adapters): a change from the plan's "skipped" (DEV-2).
- **OPEN Q1 (departure from the owner's wording "Redis/RQ dispatch").** A PostgreSQL loop, not an RQ job: l.608 gives RQ dispatch, backpressure and rate limit and PostgreSQL the job state, a sweep dispatches nothing and l.1801 recovers by a PostgreSQL scan; a net that recovers lost tasks should not depend on Redis; no Redis container or fake exists in this goal. `rq 2.11` ships `rq.cron` for a later wrapper (needs Redis and INTG-02; owner-gated). No RQ code was written or run.
- **DEC-2 (deadline outcome; l.395, l.2119, l.2120, BR-11 l.255, FR-AI-07 l.573, l.1907, l.503, BR-38 l.282; coordinator ruling for the owner's "make it match the SRS").** Only l.2119 says "keep the run FAILED", and only for exhausted scene retries; l.2120, BR-11, FR-AI-07 and l.1907 say a failed accepted request still counts toward the cap and the run returns to script review. On the 6 h deadline: the generation ends `FAILED` (safe code `VIDEO_DEADLINE_EXCEEDED`, `retryable` false, compute reservation settled once when started and released once otherwise), the unit is never refunded (the quota port has no refund method; no quota code), and the run returns to `SCRIPT_REVIEW` with a new `adult_wait_started_at`, `job_state` FAILED, `error_code` the safe code, owner lock kept, `finished_at` NULL (the path of a refused admission, l.503); when the accepted count is 3 the run ends `FAILED`, lock freed (l.2119). Implemented with `ProgressEvent.return_to_script_review` (only the deadline pass sets it) and one branch in T-1a `_apply`; no DDL, and it does not contradict the T-1a/T-1b state machine (`FAILED` generation, `SCRIPT_REVIEW` is a state every failed-request path already reaches). The same story cannot be requested again (its review is spent, as after a rejection); the way back is a rewrite, a confirmation and then a request with a quality reason, one slot spent. **Stage 2 (DEV-3, review P1-1):** that way back did not exist through the real routes (the rewrite gate reopened a confirmed script only after `REJECTED_BY_ADULT`; the first version of this note called it "proved" from a database shortcut). Fix without DDL: the T-1b gate `_has_rejected_video` in `parent_story_repository.py` is now `_has_spent_video` and also accepts a `FAILED` generation on the latest confirmed revision (the run must be in `SCRIPT_REVIEW` there; only the deadline returns a run to the script review with a `FAILED` generation). Chosen over excluding `FAILED` from `consumed` in `_insert_intent`, which needs DDL (`uq_vg_review_consumed` allows one non-rejected generation per review). A failed request still counts toward the cap, no refund. **Rewrite door:** when three rewrites are already spent (four revisions) no rewrite can lead to a request, so the deadline ends the run `FAILED` and frees the lock (`_rewrite_door_open`), the same outcome as a spent cap, instead of a script review that only the idle close could end.
