## 1. What changed

Backend (under `backend/src/sketch2life/interfaces/http/`):
- `routers/teacher_ai.py`: `_require_teacher` is deleted (with its `select` and BE1 model imports). The three POST routes (`lesson-plan-suggestions`, `sketch-decks`, `lesson-visuals`) call `be1_common.require_assignment(db, principal, organization_id, roles={"teacher"})`, then `_require_modal_dev()` (order unchanged: an out-of-scope caller never learns the provider configuration). The code `TEACHER_ORGANIZATION_ACCESS_REQUIRED` stays unused in `error_envelope.py` (`STATUS_MESSAGE_ONLY`); that hot file is not touched.
- `routers/parent_profiles.py`: `_require_active_parent` raises 404 `PROFILE_NOT_FOUND` ("Profile was not found", the family's own not-found body) instead of 403 `ACTION_NOT_ALLOWED`. The 503 `PARENT_STORE_UNAVAILABLE` path is unchanged. `PARENT_ERROR_RESPONSES` drops 403 and describes 404 as "not found, or the caller is not an active Parent".
- `routers/parent_story_runs.py`: `_require_parent` raises 404 `RESOURCE_NOT_FOUND` instead of 403 `ACTION_NOT_ALLOWED` (nine call sites, call order unchanged). `_PARENT_STORY_ERROR_RESPONSES` and `_HISTORY_RESPONSES` drop 403.
- `openapi_contract.py` (hot file, serial): the 403 row is removed from all 12 M2 Parent operations (5 profile, 7 StoryRun). `POST /v1/parent/profiles` and `GET /v1/parent/profiles` had no 404 row, so their 403 row is replaced by a 404 row ("The caller is not an active Parent"); the other 10 keep their 404 row with the description amended ("..., or the caller is not an active Parent"). The runtime-only cancel and delete operations lose their 403 through the router response map.

No DDL, no new route, no change to `be1_registry.py`, `be1_models.py`, `be1_common.py`, `app.py`, `error_envelope.py`. No capacity, billing, quota or payment code.
