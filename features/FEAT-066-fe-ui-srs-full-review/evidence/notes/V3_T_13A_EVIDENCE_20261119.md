## 1. What changed

Backend (`backend/src/sketch2life/`):

- `infrastructure/persistence/parent_story_repository.py` (**hot**): `_accept_lifecycle_command` now finds the run with `_owned_run_access(..., lock=True, teacher_capable=True)` (new; `_owned_run` is a thin wrapper that returns the row only). The Teacher assignment is re-read there under the run lock (`FOR SHARE` on the assignment row is the T-4a1 port). The receipt lookup uses the command scope (`_command_scope`); the aggregate, outbox and audit rows copy the run's OWNER scope (`actor_scope_kind`, `actor_scope_ref` of the run row), with `organization_id` = the organization for an `ORGANIZATION` run and `None` for a Parent run (byte for byte as before). `_upsert_parent_aggregate` became `_upsert_run_aggregate(scope_kind, ...)`. New module helper `_lifecycle_reason_code`: `TEACHER_CANCEL_REQUESTED` / `TEACHER_DELETE_REQUESTED`, the Parent codes unchanged. The class state of a Teacher is checked after the replay and before the revision. `_owned_run` got the missing `-> Any`.
- `interfaces/http/routers/parent_story_runs.py` (**hot**): `POST {id}/cancel` and `DELETE {id}` call `require_story_run_actor` where `_require_parent` stood and build the service with `_service_for(db, actor)`; their 404 response text is the actor text of T-4a1. The video-saga hook `_meet_video_saga` runs only for a Parent (hand-off H6).
- `infrastructure/persistence/story_lifecycle_store.py`: the eight Parent-only sites take the run's own kind: `lifecycle_state`, `_snapshot` (new field `scope_kind`), `finalize_deleted` (aggregate and `lifecycle.completed` audit), `delete_pending_runs_without_event`, `insert_reconciliation_event`, `reconciliation_event_statement(scope_kind=...)`, `_upsert_aggregate(scope_kind=...)`. `organization_id` is NULL for a Parent row and the scope ref for an `ORGANIZATION` row.
- `infrastructure/persistence/be1_lifecycle_consumer.py`: `handle` accepts the two scope kinds (anything else is `LIFECYCLE_EVENT_INVALID`); `SqlLifecycleReceiptStore._ensure` and `SqlLifecycleAuditWriter.write_exception` write `owner_scope_kind = scope.kind` and `organization_id = organization_id_of(scope)`; the "ai" step calls `record_lifecycle_notice` for every kind with the reason code of `NOTICE_REASON_CODES` (`PARENT_STORY_RUN_DELETED` unchanged, `TEACHER_STORY_RUN_DELETED` for an organization run).
- `application/ports/core_foundation.py`: `LifecycleNoticePort.record_lifecycle_notice(notice_id, scope, story_run_ref, reason_code)` added; `record_parent_notice` stays on the port.
- `infrastructure/ai_jobs/sql/repository.py`: `SqlParentLifecycleNoticeStore.record_lifecycle_notice` (the class name is kept: `backend/tools/run_be1_lifecycle_consumer.py` builds it). Parent: as before. `ORGANIZATION`: a COMPLETE notice with `organization_id` = `owner_scope_ref` = the organization, `story_run_ref` = the run, session, job type and subject NULL, `applied_count = 0`, `ON CONFLICT DO NOTHING`. `record_parent_notice` now delegates (and still refuses a non-Parent scope).

Not touched (deviations from the allowlist, all because nothing was needed): `application/services/parent_story_runs.py`, `application/ports/story_run_lifecycle.py`, `application/ports/ai_jobs.py` (the existing `CancellationNotice` already accepts the organization shape), `infrastructure/ai_jobs/fakes.py` (it has no lifecycle-notice recorder), `interfaces/http/openapi_contract.py` (cancel and DELETE are not in that file; their documented 404 text lives in the router), migrations, `core_lifecycle_store.py`, `error_envelope.py`, `app.py`, web, mobile, Bruno, seeds, DECISIONS and approval files.
