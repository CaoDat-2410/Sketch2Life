## 1. What changed

Backend (`backend/src/sketch2life/`):

- `application/ports/story_run_actor.py` (new): `RunActor` (kind PARENT or TEACHER, `account_id`, `command_scope_kind`), `TeacherRunAccess` (`class_id`, `class_state`, `writable`) and the `TeacherRunAccessPort` protocol. No table, no HTTP.
- `infrastructure/persistence/teacher_run_access.py` (new): `SqlTeacherRunAccess.resolve`, one query over BE1 tables only (managed profile, classroom, assignment, identity); `FOR SHARE OF be1_organization_assignments` when `lock`.
- `interfaces/http/story_run_actor.py` (new): `require_story_run_actor(db, principal) -> RunActor` (active identity, issuer match, role `parent` or `teacher`; anything else is the uniform 404 `RESOURCE_NOT_FOUND`).
- `infrastructure/persistence/parent_story_repository.py` (**hot**): the repository takes an optional `actor` and `teacher_access` (None = the Parent repository of before). New `_owner_clauses` (owner predicate), `_command_scope` (receipt and review scope), `_refuse_teacher`, `_teacher_run_access`, `_typed_profile_refs`; `_owned_run` gets `teacher_capable` and `write`. Only `get_run`, `confirm_context`, `confirm_subject`, `confirm_story_revision` pass `teacher_capable=True` (the last three also `write=True`). `_find_idempotency_receipt`, `_store_idempotency_receipt`, `_store_pending_idempotency_receipt`, the two review inserts use the command scope; `_owned_run` and `_receipt_run_purged` use the owner predicate.
- `interfaces/http/routers/parent_story_runs.py` (**hot**): `GET /{run_id}`, `context-confirmation`, `subject-confirmation`, `script-confirmation` call `require_story_run_actor` where `_require_parent` stood and build the service with `_service_for(db, actor)` (`_service(db)` for a Parent, so every existing fake of `_service` still works; `_teacher_service(db, actor)` for a Teacher). New `_ACTOR_STORY_ERROR_RESPONSES` (404 text). No path, body or status change for a Parent.
- `interfaces/http/openapi_contract.py` (**hot**): text only. The 404 row of the four operations reads "neither an active Parent nor the Teacher currently assigned to the child's class"; the 409 rows of the three confirmations add "the Teacher's class is not active". No route added or removed.

Not touched: migrations, `error_envelope.py`, `app.py`, `be1_models.py`, `be1_registry.py`, `uploads/resolvers.py`, `story_video/*`, the lifecycle worker, billing or capacity files, web, mobile, Bruno, DECISIONS and approval files. `application/services/parent_story_runs.py` (on the plan allowlist) needed no edit: the service passes the principal through and the repository holds the actor.
