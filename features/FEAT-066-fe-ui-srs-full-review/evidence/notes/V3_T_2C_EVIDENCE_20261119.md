## 2. Decisions (T-2c-DEC-n, SRS-cited; they carry the plan's T2C-D1..D9)

- T-2c-DEC-1 (idea route, T2C-D1; l.1665, FR-P-03 l.512, BR-23 l.267, l.1413): key 1-128, body `AddRunIdeaRequestV1` (`extra=forbid`, strict): `expected_run_revision` required; text (trimmed, 1-500) and/or `audio_ref` (`upl_...`), or one `transcript_correction {base_revision, text}`; mixing the groups or sending none is 400 `INVALID_REQUEST`. Allowed states `INPUT_PROCESSING`, `INPUT_REVIEW`, `SUBJECT_REVIEW`, else 409 `INVALID_STATE_TRANSITION`; stale revision 409 `STALE_REVISION` with `current_version`. A text or audio command writes input revision N+1 and copies every other column forward (drawing, context and its confirmation, voice, typed idea). A correction writes only a transcript revision. A fresh command on a purged run is 409; a replay returns the lifecycle projection (union response model). Receipt `SUBMIT_IDEA`, scope `STORY_RUN/{id}`, fingerprint over the body, stored 202. The same audio again with another key is 409. A typed text that would no longer fit beside a CONFIRMED transcript (over 500 together) is 400 with `field_errors [{text, TOO_LONG}]`.
- T-2c-DEC-2 (audio admission, T2C-D2; l.982, BR-23, l.1942, l.1664): `resolve_completed_upload` (purpose `RUN_AUDIO`, this run, caller scope, `CLEAN`), uniform 404 on every miss; declared and real size at most 20,000,000 bytes (the session already refuses more: 413 `AUDIO_TOO_LARGE`); duration at most 120 s (120,000 ms, rounded up) read from the verified bytes; over a limit 413 `AUDIO_TOO_LARGE`; unreadable or non-PCM WAV, an MP4 without `moov`/`mvhd`, a hostile box 422 `UPLOAD_CONTENT_MISMATCH`; a missing object 422 `UPLOAD_INCOMPLETE`, a tampered one 422 `UPLOAD_CHECKSUM_MISMATCH`, a storage fault 503 `STORAGE_UNAVAILABLE`. The MP4 parser reads box headers only and covers `moov` after `mdat`, 64-bit sizes, size 0, `mvhd` v0 and v1, timescale 0, the unknown-duration marker, overflow, a box that leaves its container, and a cap of 4,096 boxes per level. Upload policy: `RUN_AUDIO` enabled (Q-2c-1: the SRS lists no type; the two the Android recorder produces); signature `audio/mp4` = `ftyp` at bytes 4-8; `ParentRunAudioResolver` plus `ensure_accepting_audio`. - T-2c-DEC-3 (ASR step behind a port, T2C-D3; OD-13, l.731): `SpeechTranscriberPort.transcribe(request) -> result`; `FixtureSpeechTranscriber` answers only for an explicit audio SHA-256 and otherwise fails with `ASR_UNAVAILABLE`. `app.state.speech_transcriber` defaults to `None`: the transcript stays `PENDING` and the run waits (cancel works, tested). - T-2c-DEC-4 (transcript confirmation, TD-04, T2C-D4; l.512, l.1713, l.871, l.1726, l.1829): `POST /v1/story-runs/{run_id}/transcript-confirmation`, key required, body `{expected_transcript_revision, transcript_sha256, confirmed: true}`, 200 `ParentTranscriptConfirmationV1 {request_id, story_run_id, transcript_revision, state "CONFIRMED", run_revision, run_state}`. Wrong revision or hash 409 `STALE_REVISION` with `current_version` = the latest transcript revision (also when the live row is already `CONFIRMED` and the hash differs: the request is old whatever the state, l.1699; review F3); state not `NEEDS_CONFIRMATION` 409 `INVALID_STATE_TRANSITION`; the same revision and hash again 200 with nothing written (a second receipt with its own key).
