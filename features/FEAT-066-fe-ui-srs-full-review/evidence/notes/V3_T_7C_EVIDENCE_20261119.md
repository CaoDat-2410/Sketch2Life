## 1. What changed

Code only. No migration, no model change, no new error code (`error_envelope.py`, `core_store.py`, `be1_models.py` untouched). Line numbers are re-pinned at this tree (`be1_registry.py`: `create_profile` at 1176, helpers 1012-1175; the plan's 735-826 and the review's 796-886 are stale).

- `routers/be1_registry.py` (`POST /api/be1/v1/organizations/{organization_id}/classes/{class_id}/profiles`). `create_profile` is now a keyed command: `Idempotency-Key` (1-128, `parse_idempotency_key`), strong `If-Match` (the T-7b class revision, `be1_classrooms.revision`), 201 body `{contract, child_id, class_id, enrollment_id, display_name, age_months, data_origin, class_revision}` plus `ETag`. Order: class by (organization, id) in any state (404) -> Teacher row of this class (`_require_m2_assignment(roles={"teacher"})` plus the class-scoped row check; Manager 403, guide/observer 403, org-wide, other-class, other-organization, Parent, Platform Admin 404) -> key -> `If-Match` -> `class_lock_select` FOR UPDATE -> receipt replay (stored references; `db.rollback()`) -> stale revision (409 `STALE_REVISION`, `current_version`, `ETag`) -> class must be `active` (409 `INVALID_STATE_TRANSITION`) -> mode matrix -> age rule -> one `ManagedProfileModel(...)` plus one `EnrollmentModel` in one flush -> `audit("profile.enroll")` and `event("be1.profile.enrolled.v1")` as before -> receipt -> one commit. A commit `IntegrityError` rolls back and replays the winner (as `create_class`). New helpers: `_profile_receipt_scope`, `_profile_fingerprint`, `_profile_created_body`, `_replayed_profile`, `_profile_create_mode` (the matrix), `_refuse_real_profile` (the gate). `get_class(write=)` is not used here: the locked class row is checked directly for state (same effect as T-7b-DEC-5; the lock is FOR UPDATE, stronger than the FOR SHARE of other class writes, and serialises creates with state and assignment commands).
- `contracts/schemas/be1_runtime.py`: `CreateProfileRequest` loses `class_id` (path only), gains optional `consent_id` (`Identifier`); `display_name` keeps `^Synthetic .+$`, min 11, max 200; `age_months` 36-120; `extra=forbid` (so `class_id`, `child_id`, `purpose_ref`, `data_origin` give 400 `INVALID_REQUEST` with `field_errors [{field "<unknown>", code UNKNOWN_FIELD}]`; the envelope never echoes the client's field name, so the review's expected `field: "class_id"` is `"<unknown>"`).
- `infrastructure/config/settings.py`: one field `real_profile_data_enabled: bool = False` (`SKETCH2LIFE_REAL_PROFILE_DATA_ENABLED`, OD-06).
- `interfaces/http/openapi_contract.py`: row override (purpose, `request_inputs` with `Idempotency-Key*`, `If-Match`, body `{display_name*, age_months*, consent_id}`, verification) and the operation joins `IDEMPOTENCY_MISMATCH_OPERATION_KEYS` (now 29). `openapi_contract_amendments.py`: the 201 example gains `enrollment_id`, `class_revision`. No new operation; counts unchanged (176 runtime, 155 catalog).

### OWNER-VISIBLE items (decide or acknowledge before X-19 or any real pilot)

- **O-1 (review F-01, T-7c-DEBT-1): the receipt fingerprint contains the child's name under a plain SHA-256.** `be1_command_receipts.request_fingerprint` (never purged) stores a SHA-256 of `{principal, scope, display_name, age_months, consent_id, if_match}`. The principal and scope are readable with the table, so they only separate domains; the search space (a short name, 85 ages, a small revision) lets a guess be confirmed. Acceptable today only because every writable row carries a `Synthetic ` name and the gate writes no receipt. REQUIRED before X-19 or any real pilot: change it to a keyed HMAC (server secret), or fingerprint only `(age_months, if_match, consent_id)` plus a per-row nonce and compare the name against the stored profile on replay; and list the fingerprint in the FR-C-10 deletion path (SRS l.502). The wording is corrected in code and in this note ("domain-separated, not keyed"; it was "salted").
- **O-2 (review F-02): unthrottled audit rows on repeated real-gate attempts.** With `real_profile_data_enabled` on, each call that carries a `consent_id` of the class writes one `denied_consent_pending` audit row and commits (no receipt, so no dedupe). An assigned Teacher can fill the audit table at request rate. The flag is off by default and every other `deny_pending_consent` caller has the same property. Rate limit or dedupe by (actor, consent) when X-19 lands.
- **O-3 (review F-04, Q-1, TD-28): create does not bump the class revision, and that is an inference.** SRS l.1651 says only "expected class revision"; l.1699 says an old request gets `STALE_REVISION`; neither says create bumps it, and Draft 5 TD-28 words the counter as changing on state, assignment and enrollment moves. The default (no bump) is defensible but is an inference: the token guards state, assignment and move changes only, and two creates under one revision both succeed (PG test: 20 concurrent creates, revision stays 1). Owner may flip it: one line (`classroom.revision += 1`) plus the 20-create test.
