## 3. Route and behaviour

`GET /v1/jobs/{job_id}`, bearer token required. Only GET exists (POST, PUT, PATCH, DELETE answer 405; there is no completion, cancel or retry path). 200 body `AiJobStatusV1`; 304 empty body with the ETag; 400, 401, 404, 503 as in DEC-11. At HEAD no job type is registered, so every job answers 404 until a producer registers its type.

## 9. Debt for the first producer task (T0.4-DEBT)

- **T0.4-DEBT-1 (review F-1, per-class role).** `ActorMembership` carries `roles` (union over the organization) and `class_ids` (union over every class with any assignment role); the reader derives the projection role from the union. Rule for every producer that registers a job type: its `scope_rule` MUST NOT treat membership in `class_ids` as sufficient for a result-bearing read. It must either (a) accept only classes where the actor holds the `teacher` role, which needs the per-class role first, or (b) register `eligibility` so that result refs are withheld unless the actor holds `teacher` for that job's class. The first producer task (T-3b, or the first one to register a job type) must, before registering, extend `ActorMembership` with the per-class roles (`GrantedClass.role` is already available from the loader, for example `classes: Mapping[str, frozenset[str]]`) and let the reader derive the projection role from the role held for the scope the rule accepted, with a test (observer in class A plus teacher in class B reads a class-A job: 404 or no result refs). A `school_admin` who also teaches one class must not receive TEACHER result refs for another class. Nothing leaks at HEAD because no job type is registered.
- **T0.4-DEBT-2 (review F-2, latency existence signal).** A missing id, an unregistered type and a non-adult role return after one repository read, while a registered job in another organization also pays the three loader queries. Status codes and bodies are identical (tested); latency is not. Residual risk accepted for T0.4 (opaque ids, weak oracle). Rule for producers: do not add per-kind lookups that are skipped for missing ids without first adding a constant-cost dummy membership read to the not-found branch; the first producer decides whether to add that dummy read.
