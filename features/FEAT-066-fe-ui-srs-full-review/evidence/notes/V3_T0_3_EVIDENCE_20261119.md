## 1. What changed

Backend (under `backend/src/sketch2life/`):
- `interfaces/http/routers/health.py`: `GET /health` unchanged. New `GET /health/live` (public, `{"status":"ok"}`, no dependency call, in the runtime schema). New `GET /health/ready` and `GET /metrics` (`include_in_schema=False`, guarded).
- `interfaces/http/probe_access.py` (new): the access guard `probe_access_denial(request)` plus the shared loopback helpers (`is_loopback_address`, `is_local_host_header`, `is_direct_loopback_request`).
- `interfaces/http/metrics.py` (new): `MetricsRegistry` (lock-protected counters, one histogram, one gauge, hand-written Prometheus text 0.0.4) and `HttpMetricsMiddleware` (pure ASGI).
- `interfaces/http/app.py`: the two private loopback helpers became import aliases of the shared ones (same code, same behaviour of the StoryRun-lite demo guard; the now unused `ip_address` and `urlsplit` imports were removed); three lines after the last `add_middleware` create the registry, store it as `application.state.metrics_registry` and add `HttpMetricsMiddleware` as the outermost user middleware.
- `infrastructure/config/settings.py`: optional `ops_probe_token: SecretStr | None`; blank or whitespace-only input is unset; `Settings` gained `hide_input_in_errors=True`.
- `compose.yaml`: `SKETCH2LIFE_OPS_PROBE_TOKEN: ${SKETCH2LIFE_OPS_PROBE_TOKEN:-}` pass-through (no default value, no secret in the file).

No DDL, no migration, no new dependency. `GET /api/be1/v1/health` untouched.

| T0.3-DEC-3 | `ready` and `metrics` are allowed only with the configured bearer credential (SHA-256 digests compared with `hmac.compare_digest`; exactly one `Authorization` header, scheme case-insensitive), or, only when `env` is `local` or `test` AND no credential is configured, for a direct loopback request (loopback client and server, local Host, none of `forwarded`, `x-forwarded-for`, `x-real-ip`). | T0.3-DEC-4 | Denial bodies (plan review F-2). The two paths are not in `CONV1_PREFIXES`, and `error_envelope.py` is not edited (T0.4 owns the next edit of that tuple). 401 (credential configured, missing or wrong): the shared error body built with `build_error_body` (the six §9.8 fields plus `request_id`) (code `AUTH_REQUIRED`), `X-Request-ID`, `WWW-Authenticate: Bearer`. 404 (no credential configured and not an allowed loopback): a plain Starlette 404 that is byte-identical to the answer for an unknown path (`{"detail":"Not Found"}`). The same holds for every other method (POST, PUT, PATCH, DELETE, OPTIONS, HEAD, TRACE): those are registered on the two hidden paths only to raise the same 404, so no 405 or `Allow` header reveals them (review P3-2). So 404 vs 401 reveals only whether a credential is configured; accepted. The presented value is never logged or echoed (tested). | SRS §9.8 l.849; plan review F-2, F-7 |
| T0.3-DEC-5 | Readiness bound (plan review F-1). The probe opens its own short-lived connection (new engine from the runtime engine URL, `NullPool`, disposed at the end) with libpq `connect_timeout=2` and server `statement_timeout=2000 ms`, so the bound is real and the request pool is never used. It runs in `anyio.to_thread.run_sync(..., abandon_on_cancel=True)` under `fail_after(4 s)` as an outer bound for what libpq does not cover. At most 2 probe threads exist at once; further probes answer `down` without a thread; a slot is released exactly once (by the thread, or in a `finally` by the caller if the thread never started, which also covers cancellation; review P3-1). Any exception, timeout, missing runtime, missing engine or `database_error` is `down`. The 503 body is exactly `{"status":"not_ready","checks":{"database":"down"}}`; no host, URL, credential or exception text. `Cache-Control: no-store`. Storage, scanner, identity provider and queue are not probed (no new network calls in v3a). | l.612, l.814 |
| T0.3-DEC-6 | The setting (plan review F-4). `SKETCH2LIFE_OPS_PROBE_TOKEN` empty or whitespace-only (Compose passes `${VAR:-}`) is unset and does not fail startup. A non-empty value shorter than 32 characters, or containing a character outside visible ASCII, fails startup with a message that does not echo the value. To make that true, `Settings` got `hide_input_in_errors=True` (pydantic otherwise prints the raw input dict, including the credential). Side effect: no `Settings` validation error prints input values any more (an improvement for `database_url` too). `production` with no credential is allowed: the probes are then simply 404. | design; plan review F-4 |
| T0.3-DEC-7 | Metrics: `sketch2life_build_info{service}`, `sketch2life_process_start_time_seconds`, `sketch2life_http_requests_total{method,status_class}` (method from a fixed set, anything else `OTHER`; class `1xx`..`5xx`), `sketch2life_http_request_duration_seconds` histogram (fixed buckets 5 ms to 10 s, no labels), `sketch2life_http_requests_in_flight`. No route, path, user, organization, run or job label, so series count is bounded (tested with 50 unique unmatched paths); no business counts (aggregates are X-11); per process (the container runs one worker; the HELP text says so). A scrape touches no database (tested with a stub runtime and, on PostgreSQL, a statement listener). | l.1711 |
| T0.3-DEC-8 | The metrics middleware is the outermost user middleware (last `add_middleware`; asserted by a test). An exception that reaches it is counted as `5xx` and re-raised, because the unhandled-exception handler sits outside user middleware (plan review F-7). | plan review F-7 |
| T0.3-DEC-9 | `ready` and `metrics` stay out of Swagger and the catalog (they are mounted and reachable, tests call them). `/health/live` is in the runtime schema as an uncatalogued operation like `/health`; the FE projection is an explicit allow-list and contains none of the three. | plan open question 2; review |

## 3. FE and client impact

None for web or mobile (nothing calls the new paths). Operators gain `ready` and `metrics`. Compose note: a host `curl` through the published port is not loopback inside the container, so use the credential from the shared `.env`, or `docker compose exec api` (loopback; only while no credential is configured). `/health` stays the Compose healthcheck. Platform Admin bearer access to the probes is NOT offered (OPEN, not decided): only the System Operator credential works.
