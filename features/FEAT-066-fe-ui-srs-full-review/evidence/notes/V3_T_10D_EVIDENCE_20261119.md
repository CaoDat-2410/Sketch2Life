## 5. OWNER-VISIBLE behaviour change (TD-24, T-10d-DEC-6)

Before: a Teacher could share a lesson version with a Parent group, a named Parent or the school only after a School Manager had approved a PUBLIC request for that version (409 `PUBLICATION_REQUIRED` otherwise), and Parents read shared versions only if the version was `APPROVED`.
After: a Teacher can share a version in **any** review state (DRAFT, PENDING_REVIEW, CHANGES_REQUESTED, APPROVED) with a named Parent (who must accept), with an active Parent group (no further consent step: every active member reads at once) or with the school, with no Manager approval. A Manager decision is needed only for PUBLIC. TD-24's text says a "reviewed" version suffices; the code has no "reviewed" state, so this change reads it as "authored by the sharer", which is broader than TD-24's wording. The SRS settles the rule (FR-PL-05 l.2646, FR-PL-06 l.2647), so the task proceeded on it.

OWNER-VISIBLE items added by implementation review R1 (no code change; the owner decides):

- **TD-24 breadth.** A share is now allowed for a version in any review state (DRAFT, PENDING_REVIEW, CHANGES_REQUESTED, APPROVED). The SRS supports it: FR-PL-05 l.2646, FR-PL-06 l.2647, BR-51 l.2676, l.2565, l.2587-2588. A "reviewed-only" restriction (for example APPROVED only, or a Teacher confirm flag) is a product choice, not an SRS requirement, and would be a separate task with a new check or state.
- **Unreviewed Teacher content reaches Parent StoryRuns.** Unreviewed Teacher content can now reach a Parent StoryRun pin and the story pipeline: the Parent StoryRun lesson lookup serves a privately shared DRAFT, PENDING_REVIEW or CHANGES_REQUESTED version. The SRS has no gate for this (human review is tied to AI-origin outputs, BR-53, and to PUBLIC, FR-PL-05); authoring validation is structural only. "Shared to my group" now means "shared before any Manager review", including into children's stories.
- **School share and Parents (pre-existing behaviour, owner question).** Test d pins that a school (ORGANIZATION) share never reaches Parents, while the SRS role matrix l.2587 ("School lesson: Parent uses it when school/group/invite grant active") reads wider. The behaviour is as at HEAD and T-10d does not change it; the test turns the current reading into a regression guard. Owner question: is a school share meant to reach the school's Parents, or only Teachers and Manager?
- **School visibility shows the current version (pre-existing).** `list_lessons` and `get_lesson` show colleague Teachers a SCHOOL lesson through `current_version_id`, not the version the school grant names (SRS l.2565 allows school-wide view). Before T-10d a later draft version was already visible this way; the first exposure of a DRAFT can now come from a share. No change.
