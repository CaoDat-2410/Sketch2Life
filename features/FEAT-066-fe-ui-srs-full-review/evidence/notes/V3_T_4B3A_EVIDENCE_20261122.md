## 1. What changed

No migration, no DDL, no route, no schema member, no error code. Source under `backend/src/sketch2life/`:

- `interfaces/http/story_run_actor.py`: `story_run_repository(db, actor)`. A Parent actor builds `SqlParentStoryRunRepository(db)` exactly as before T-4a1 (no actor, no access port); a Teacher actor builds it with the actor and `SqlTeacherRunAccess(db)`.
- `interfaces/http/routers/parent_story_inputs.py` (the five routes): `_require_parent` becomes `require_story_run_actor` at the same place (FastAPI still validates body and headers first; the key is parsed after the role check); the repository comes from the helper; the Teacher background tasks get the actor and the organization (`_job_actor`; a Parent task is scheduled with exactly the arguments it always had). The 404 text of the five responses names the Teacher. `interfaces/http/routers/parent_story_runs.py`: the subject confirmation drops the Teacher exclusion of the VLM rerun and passes the actor and the organization to the runner. `interfaces/http/openapi_contract.py`: the 404 and 409 text rows of rows 1 to 5.
- `infrastructure/persistence/parent_story_repository.py` (**hot**): `job_side` and `job_side_organization` constructor parameters; `_owned_run(_access)` gets `pinned` and `job_side_ok`; `_job_side_run`; the ten Teacher steps (`ensure_accepting_artwork`, `ensure_accepting_audio`, `prepare_drawing_attach`, `attach_uploaded_drawing`, `prepare_idea`, `submit_idea`, `get_transcript`, `confirm_transcript`, `reserve_story_rewrite`, `asset_owner`) pass `teacher_capable=True, pinned=True`; the eleven job-side methods pass `job_side_ok=True`; `_asset_owner` (the owner triple of the Core rows); the SUBJECT decision and the attempt count by command kind; the Teacher worker input; `_read_run_view` (the body of `get_run`, so a job-side completion can return the view); `job_side_repository`; `story_task_audit_scope`; `write_story_task_audit` gains `owner_scope_kind` and `organization_id` (defaults give every Parent call the row it always wrote).
- `infrastructure/story_inputs/{service,idea}.py`: the two services take the repository (default: the Parent one) and read the owner triple from it, so no scope is taken from the principal any more; `{runner,speech,story_generation}.py`: the runners take an optional actor and organization and use the job-side repository only when given an actor (a Parent task still builds `SqlParentStoryRunRepository(session)`).
- `infrastructure/uploads/{purposes,service,resolvers}.py`: `UploadPurposePolicy.also_roles` (default empty), `roles`; `RUN_ARTWORK` and `RUN_AUDIO` list `teacher`; role-dispatching `RunArtworkResolver` and `RunAudioResolver` (the Parent classes stay and are what a Parent gets).
- `infrastructure/persistence/story_task_reaper_store.py`: `_story_lane` (Parent kind, or `ORGANIZATION` with an occurrence pin), receipts by command kind for a Teacher run, the audit row through `story_task_audit_scope`.
- `infrastructure/story_video/repository.py`: `_finalize_receipt` finds the PENDING receipt by the run's command KIND, operation, run and key hash, not by the run's owner pair.
- `domain/story_teacher.py`: `teacher_lesson_direction` (bounded, pure). `application/ports/{story_run_actor,parent_story_inputs,parent_story_runs}.py`: `RunAssetOwner`; an `organization_id` field (never stored, never in a body) on `DrawingAttachOutcome`, `IdeaOutcome`, `SubjectConfirmOutcome` and `ParentStoryRevisionReservation`. `application/services/story_output.py`: `complete_generated_story` hands the Teacher view back instead of refusing it.
