## 1. What changed

- New `backend/src/sketch2life/interfaces/http/account_scope.py`: `load_granted_scope(db, identity) -> GrantedScope`, the one reusable reader of an account's active assignments (T0.4 imports it for membership checks; `GrantedScope.organization_ids()` is provided for that). At most three bounded queries: (1) active organizations that hold an active assignment of the subject, ordered by `organization_id`, limit 101; (2) the distinct roles per listed organization; (3) classes: assignment joined to `be1_classrooms` on `class_id` AND `organization_id` equal to the assignment's organization, active classrooms only, ordered by organization, class, role, limit 501. Parent and Platform Admin accounts (no organization scope) return empty lists with zero queries, even if stray assignment rows exist.
- `routers/auth_registration.py`: `CurrentAccountResponse` keeps `role`, `state`, `role_revision` and gains `scope` (`GrantedScopeResponse`: `organizations[{organization_id, display_name, roles}]`, `classes[{organization_id, class_id, display_name, role, state}]`, `accounts{account_id, managed}`, `permissions` always `[]`, `truncated`). Header `Cache-Control: private, no-store`. New constant `ME_SETUP_REFUSAL_STATUS = 403` (one switch point). OpenAPI description and `responses` (401, 403, 503) extended; field descriptions carry the vocabulary notes.
- No new route, no DDL, no migration, no model change. The OpenAPI catalog counts are untouched (154 operations, 14 uncatalogued; `/me` stays in the uncatalogued set), and `test_openapi_contract_catalog.py` was not edited.

## 2. Decisions (draft labels)

| Label | Decision | Basis |
|---|---|---|
| T0.2-DEC-1 | The setup refusal stays 403 `ACCOUNT_SETUP_UNAVAILABLE`. Recorded deviation from SRS l.866 (lists the code under 409; l.864 reserves 403 for `ACTION_NOT_ALLOWED`). Reason: the Parent mobile client (`apps/ui-mobile/src/parent/infrastructure/auth/ParentAuth.ts:192`) branches on `response.status === 403` to show the "account has no role yet" message; a 409 would only degrade that message to the generic "try again later" text (sign-in is refused either way; the error `code` still passes through). One switch point: `ME_SETUP_REFUSAL_STATUS`, to become 409 together with the Parent client change (re-grep status branches on `/me`, including the teammate-shared `.worktrees/ui`, before switching). | TD-25 rule "409 after a check of the clients; if any depends, keep 403" (source plan l.496, T0.2 row l.139). Not OD-18 (plan review F-1: OD-18 does not govern `/me`). |
| T0.2-DEC-2 | Scope = informational for client routing; every route still re-authorises server side (stated in the OpenAPI description). `/me` path unchanged (`/api/auth/v1/me`, C-D9, TD-01). | SRS l.794 ("role và scope được cấp"), l.1637 |
| T0.2-DEC-3 | Only active assignments in active organizations. A class is listed only if its classroom exists, belongs to the assignment's own organization, and is `active` (dangling `class_id`, class of another organization, `locked`/`archived` classes are dropped). An organization-wide assignment (null `class_id`) appears in `organizations[].roles` only; classes are never enumerated for it. `organizations[].roles` are the assignment roles held in the organization (org-wide or class-bound), unique and sorted; `guide`/`observer` are assignment roles, not SRS product roles (l.1602). A class appears once per held role. | Plan review F-4, F-7; BE1 reads filter `active` everywhere |
| T0.2-DEC-4 | Caps 100 organizations and 500 classes, stable order by id; `truncated` true when a cap cut either list. A truncated caller uses the paged per-organization routes (OpenAPI description). `/me` is not a list API, so the l.1640 cursor rule does not apply. | Plan review F-5 |
| T0.2-DEC-5 | `scope.accounts` = `{account_id, managed}`. `account_id` is the caller's own internal account id (not the Firebase UID, not the e-mail), returned only to its owner with `no-store`; the refusal carries no id. This is a new exposure of the own id to Parent and Teacher roles (plan §8 Q1 said "already seen in admin flows"; review R-2 corrected that: only other accounts' ids are shown there). Acceptable but optional per the review; no client reads it. To drop it: remove `account_id` from `ScopeAccountsResponse`/`GrantedScope` (two places) and the matching tests. `managed` (`NONE` or `PLATFORM`) is a provisional vocabulary not defined by the SRS; clients treat unknown values as `NONE` (review F-3). | SRS l.493, l.1637; plan review R-2, F-3 |
| T0.2-DEC-6 | `permissions` is always `[]` until the Content Admin permission store (TD-11). Class `state` is passed through unchanged (SRS "suspended" vs stored `locked`, TD-08); since only active classes are listed it is always `active` today. | Source plan TD-11, TD-08 |
