## 1. What changed

Backend (under `backend/src/sketch2life/`):
- `infrastructure/config/settings.py`: new `profile_receipt_hmac_key: SecretStr | None` (`SKETCH2LIFE_PROFILE_RECEIPT_HMAC_KEY`); a blank or whitespace-only value is unset, exactly as `ops_probe_token` (a `mode="before"` validator, plan review F-01). Policy validator: a non-blank key shorter than 32 bytes is a `ValueError` in every environment; with no key, `local` and `test` generate a per-process `secrets.token_urlsafe(48)`, `staging` and `production` never do, and `real_profile_data_enabled` with no key in staging or production is a `ValueError`. Messages never contain the key (`hide_input_in_errors` is on; the length check sits in the after-validator). New `profile_gate_account_limit` (5), `profile_gate_ip_limit` (20), `profile_gate_window_seconds` (60) with bounds (plan review F-07: the numbers are provisional and tunable, X-18; after implementation review F-04 the upper bounds are 200 per account and 1000 per address). The receipt key must also differ from the room-code key (review F-01). Constant `MIN_PROFILE_RECEIPT_KEY_BYTES = 32`.
- `interfaces/http/routers/be1_registry.py`: `_profile_fingerprint` is now HMAC-SHA-256 (hex, 64 characters, fits the column and its CHECK) over the canonical JSON `{domain: "be1.profile.create.receipt", v: 2, principal, scope, display_name, age_months, consent_id, if_match}`, keyed by the new setting (never the room-code key). The create receipt's `response_json` gains `fp_v` (2) and `fp_kid` (first 8 hex characters of an HMAC of a fixed label under the key: a key id, not the key). `_replayed_profile` compares with `hmac.compare_digest` on ASCII bytes (a tampered non-ASCII value is a mismatch, not a 500) and also requires `fp_v` and `fp_kid` to match; a v1 row, another format version or another key id answers 400 `INVALID_IDEMPOTENCY_KEY`. `_profile_receipt_key(runtime)` answers 503 `SERVICE_UNAVAILABLE` (public `PROVIDER_UNAVAILABLE`) when the key is absent or short, and is called only when needed: at a stored receipt, or after the mode matrix for the synthetic and real-gate branches (so staging with both flags off and no key still answers the 409 `SYNTHETIC_PROFILE_CREATION_UNAVAILABLE`, plan review F-12). `_charge_profile_gate` charges the limiter for the real gate only, as the first step of the gate (before the consent lookup), then `db.rollback()` and `HTTPException(429, {"code": "RATE_LIMITED"}, headers {"Retry-After": n})`. Order inside the handler is unchanged: class 404, Teacher row 404/403, key, `If-Match`, class lock, receipt replay, stale, state, mode matrix, key guard, gate charge, consent lookup.
- `interfaces/http/rate_limit.py` (new): `SlidingWindowLimiter`, process-local, one lock, injectable clock. Two buckets per call, `(operation, account)` and `(operation, ip)`; a call is admitted only when both have room and is then recorded in both, a refused call charges neither; the refusal returns whole seconds (at least 1) equal to the **maximum** of the refusing buckets' waits (review F-07). Each dimension is an LRU `OrderedDict` capped at 1024 keys; each bucket holds at most its limit of timestamps.
- `interfaces/http/be1_runtime.py`: `Be1Runtime.profile_gate_limiter` (default factory; `build_be1_runtime` builds it from the settings) and `_require_receipt_key_for_real_data`, called first in `build_be1_runtime`: a staging or production settings object with real profile data on and no key (or a short one) raises `RuntimeError` (defence for a hand-built or mutated object; the message has no key).
- `infrastructure/persistence/be1_receipts.py` (new): `purge_child_receipts(db, organization_id, child_id) -> int` deletes the organization's `be1_command_receipts` rows whose `response_json->>'child_id'` equals the child (create and move receipts, including a hashed move scope). **Not wired to any route** (a test asserts no other module uses it).
- `interfaces/http/openapi_contract.py`: the create-profile purpose text names the 429 `RATE_LIMITED` with `Retry-After` (limits are provisional, "not SRS values"), the 400 for a pre-keyed-format key, and the 503; `verification` adds l.637 and T-7c-fix. The response rows already declared 429 and 503. Counts unchanged (176 runtime, 155 catalog).
- Docs: `backend/.env.example` (blank key line with a comment), `backend/README.md` (one paragraph: key, generated local key, 503, rotation, limits, proxy-header note).
