## 2. Decisions

- T0.5-DEC-1 (answers TD-18, "fail loudly and log"): do not move the lite prefix (pinned contract, Bruno collection and handoff documents cannot be re-pointed here); raise at startup unless acknowledged, and log one WARNING when acknowledged. Basis: SRS has no demo route; `/v1/story-runs` is the real Parent surface (l.1663 create, l.1666-1669 confirmations, l.1673 cancel, l.1674 delete). Not an SRS number: TD-18 and the T0.5 row are technical decisions.
- T0.5-DEC-2: the raise condition is "the demo replaces any real route" (`collides` or `unmounted` non-empty), not only an exact-path match, because the real Parent router is removed as a whole (plan review F-2). Both numbers are reported.
- T0.5-DEC-3 (plan review F-3): the acknowledgement is validated only when the main flag is `1`. A stale `...REPLACES_PARENT_ROUTER=banana` with the flag off does not block unrelated runs; acknowledgement alone is ignored. The existing flag-value and profile/environment errors are raised first.
- T0.5-DEC-4: `application.state` carries two read-only tuples (colliding and all unmounted real routes) so a later check or admin page can state exactly what the demo hides.
- T0.5-DEC-5: the helper takes route tables, not prefixes, so it is reusable for T-2a. It reads `.routes` of the registered routers; a router that nests another included router would need that nested router listed itself (FastAPI wraps included routers; not the case for the current routers).

Plan review R1 ruling: raise-unless-acknowledged accepted; the extra variable name has no TOKEN/SECRET/PASSWORD word and the repository security validator accepts it. Citations corrected as in F-4 (l.1663, l.1673-1674; TD-18 as technical decision, not "the owner asked").
