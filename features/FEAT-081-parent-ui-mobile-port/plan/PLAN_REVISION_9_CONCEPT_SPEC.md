## Common phone chrome and classification

Every panel below has the ordered outer tree `preview article → variant-A viewport → phone → statusbar → concept-strip → app-header → phone-content → optional phone-tabs`. Within phone-content, children appear in the exact order listed for that panel. Cards contain the listed title, notices, fields, rows, and actions in document order; the spec names each grouping. Header back/step controls, field controls, state badges, and bottom tabs are children of their corresponding header/card/navigation groups.

Common phone-visible strings: `Sketch2Life` (APP COPY); `•••` (decorative status indicators, not copy); `NỘI DUNG MẪU · CHƯA CHỐT` (DESIGN ANNOTATION, excluded from app). The outside-frame preview title and the caption quoted per screen are DESIGN ANNOTATION and never app copy. Unicode check, progress dots, and inline SVG marks are icons/state cues. Every bracketed dynamic value, demo profile/story/catalog item, mock ID/hash/date, and the explicit words `MẪU`, `dữ liệu giả`, or `minh họa` is SAMPLE DATA. All other quoted product labels, buttons, explanatory and error text are APP COPY, except the explicitly identified design annotation. Where a product string itself mentions an example or unavailable capability, the frozen SRS/state rules in Plan Revision 9 decide whether it is rendered.
