## How to read this file

1. **Authentication & Tenant Scope:** Adult Teacher endpoints require `Authorization: Bearer <Firebase_ID_token>`. Role (`teacher`), organization membership, and exact class assignments (`OrganizationAssignmentModel` with `active=True`) are resolved server-side (`BR-03`, `BR-05`, `FR-C-01`). Suspended classes are readable in read routes and blocked (`409`) on mutations; archived classes are hidden (`404`) from Teachers.
2. **Error envelopes:**
   - **CONV-1 routes** (`/api/auth/v1/*`, `/api/be1/v1/*`, `/api/lesson-library/v1/*`, `/api/teacher/v1/*`, `/v1/lesson-occurrences*`, `/v1/upload-sessions*`, `/v1/notifications*`, `/v1/jobs/*`): Normalized by `error_envelope.py` into `{ "code", "message", "correlation_id", "field_errors"?, "retryable"?, "retry_after_seconds"?, "current_version"? }`. FastAPI `422` validation errors normalize to `400 INVALID_REQUEST`; `DEPENDENCY_UNAVAILABLE` maps to `PROVIDER_UNAVAILABLE`, `CONFLICT`/`INVALID_TRANSITION` to `INVALID_STATE_TRANSITION`, and `*_NOT_FOUND` to `RESOURCE_NOT_FOUND`.
   - **StoryRun actor routes** (`/v1/story-runs*`): Shared routes documented in [PARENT_API.md](./PARENT_API.md) use `ParentStoryErrorEnvelopeV1` / `ParentStoryCancelErrorEnvelopeV1`. Section 5 lists Teacher-specific create inputs (`TeacherStoryRunCreateRequestV1`), responses (`TeacherStoryRunEnvelopeV1`), and differences.
3. **Conventions & Concurrency:**
   - **Idempotency:** Keyed POST/PATCH/PUT/DELETE commands require `Idempotency-Key` (1–128 visible ASCII chars). Reusing a key with a mismatched payload returns `400 INVALID_IDEMPOTENCY_KEY`.
   - **Optimistic concurrency:** Lesson Library routes use strong ETag `If-Match: "<revision>"`; BE1 `PATCH .../profiles/{child_id}`, `PUT .../support-needs`, and `/v1/lesson-occurrences` plan/document edits pass `expected_revision` / `expected_head_revision_no` in JSON body (while `POST .../child-selections/{id}/confirmation` and `POST .../projection-confirmation` use `If-Match`). Stale writes return `409 STALE_REVISION` with `current_version`.
   - **Demo toggle & synthetic pilot guard:** When `STORYRUN_LITE_MAIN_DEMO_ENABLED=1`, `/v1/story-runs*` and `/v1/upload-sessions*` are replaced by the demo router. `pilot-assistance` routes mount only in `test` or `local` with `synthetic_pilot_enabled=True`.
4. **Status legend:**
   - `MERGED` — Live in integration (`297f2849`).
   - `pending merge (Phase D, planned)` — Planned in `tmp/phase-v4/API_INVENTORY_V4_20261125.md`, not yet implemented.
   - `owner: Billing/Capacity (not documented in detail here)` — Owned by Billing/Capacity track (`be1_billing.py`); listed for completeness without internal documentation.

Teachers share `/v1/story-runs*`, `/v1/jobs/{job_id}`, and `/v1/upload-sessions*` with Parent callers (documented in full in [PARENT_API.md](./PARENT_API.md) Sections 3–4). The table below documents `POST /v1/story-runs` (Teacher branch) and cross-references every shared route with Teacher-specific differences:
- **Response envelope (`StoryRunResult`):** Returns `TeacherStoryRunEnvelopeV1` (`story_run: TeacherStoryRunResponseV1`) with `profile_ref: { kind: "MANAGED_PROFILE", id }`, `occurrence_id`, `plan: { revision_no, plan_hash }`, `activity: { plan_activity_id, kind, snapshot_hash }`, and `TeacherRunPinSnapshotV1` instead of UUID `parent_profile_id`.

- **No activity selection / no `/v1/activities`:** Teachers pin `activity_id` (`plan_activity_id`) at creation from the approved plan; `/v1/activities`, `/activity-selection`, and `GET /v1/story-runs` history listing remain Parent-only.
